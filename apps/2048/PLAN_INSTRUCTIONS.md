# Plan 서브에이전트 지침 — 2048 게임

## 역할
너는 이 프로젝트(마크다운 블로그 + 미니 웹앱 포트폴리오)의 **Plan 단계** 서브에이전트다.
아래 요구사항을 바탕으로 구현 계획을 세우고, `apps/2048/spec.md` 파일로 저장하는 것이 유일한 임무다.
**코드를 작성하지 마라.** 계획 문서만 작성한다.

## 프로젝트 제약 조건 (CLAUDE.md 발췌)
- 순수 HTML, CSS, JavaScript만 사용. React/Vue/Svelte 등 프레임워크 금지.
- 빌드 도구/번들러 없음. 브라우저에서 파일을 그대로 열거나 정적 서버로 서빙하면 동작해야 함.
- 외부 라이브러리 사용 최소화. CDN은 허용되지만 이 정도 규모 게임에는 불필요함.
- 웹앱은 `/apps/2048/` 폴더 안에 자체 완결되어야 한다. 블로그의 다른 파일(css/, js/, index.html, post.html 등)은 건드리지 않는다.
- 모바일에서도 사용 가능해야 한다 (터치 스와이프 지원 포함).
- 다크 모드 지원 필요 (prefers-color-scheme + 수동 토글, CSS 변수 사용).

## 사용자 요청
"2048게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘"

요구사항:
- 4x4 그리드에서 방향키(↑↓←→)로 타일을 밀고, 같은 숫자 타일이 만나면 합쳐지는 2048 게임.
- 모바일에서는 스와이프 제스처로도 조작 가능해야 한다.
- 현재 점수판(score)과 최고 점수(best score, localStorage에 저장) 표시.
- 게임 오버 판정 및 재시작 버튼.
- 2048 타일 도달 시(승리) 안내.

## 산출물
`apps/2048/spec.md` 파일 하나를 작성한다. 내용에는 다음이 포함되어야 한다:

1. **개요**: 게임 설명 한두 문단.
2. **파일 구조**: `/apps/2048/` 안에 만들 파일 목록과 각 파일의 역할 (예: index.html, style.css, game.js 등).
3. **핵심 로직 설계**:
   - 4x4 보드 데이터 구조
   - 타일 이동/병합 알고리즘 (한 방향 기준으로 어떻게 처리할지)
   - 새 타일 생성 규칙 (2 또는 4, 확률)
   - 점수 계산 방식
   - 게임 오버/승리 판정 조건
4. **입력 처리**: 키보드 방향키 이벤트, 모바일 터치/스와이프 이벤트 처리 방식.
5. **UI/디자인**: 레이아웃 구성(점수판 위치, 보드, 버튼), 다크모드 대응, 타일 색상 구성 방식(숫자별 색상 매핑), 모바일 반응형 고려사항.
6. **로컬 저장**: best score를 localStorage에 저장하는 방식.
7. **작업 순서(체크리스트)**: Build 단계에서 순서대로 구현할 수 있도록 단계별 작업 목록.

계획을 다 작성했으면 `apps/2048/spec.md`로 저장하고, 무엇을 작성했는지 간단히 요약해서 보고하라 (300자 이내).
