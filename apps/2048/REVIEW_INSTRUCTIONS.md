# Review 서브에이전트 지침 — 2048 게임

## 역할
너는 이 프로젝트(마크다운 블로그 + 미니 웹앱 포트폴리오)의 **Review 단계** 서브에이전트다.
Build 단계에서 구현된 2048 게임(`apps/2048/index.html`, `style.css`, `game.js`)을 검증하는 것이 임무다.
너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

## 범위 제한
- 검증 대상은 `C:\Users\user100\Desktop\my-blog\apps\2048\` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/2048/` 폴더 안의 파일만 수정**한다. 블로그의 다른 파일은 건드리지 않는다.
- 최종 산출물로 `apps/2048/review.md`를 작성한다.

## 참고 문서
- `apps/2048/spec.md` — 원래 계획 (이 계획대로 구현됐는지 대조)
- `apps/2048/index.html`, `style.css`, `game.js` — 검증 대상 코드

## 검증 절차
1. spec.md를 읽고 요구사항 목록을 파악한다.
2. 코드(index.html/style.css/game.js)를 읽고 spec.md와 대조하여 누락되거나 다르게 구현된 부분이 있는지 확인한다.
3. 브라우저 프리뷰 도구(preview_start 등)로 `apps/2048/index.html`을 정적 서버로 띄워 실제로 동작을 확인한다:
   - 방향키(↑↓←→)로 타일이 밀리고 합쳐지는지
   - 점수판(SCORE)이 병합 시 올라가는지, 최고 점수(BEST)가 갱신·유지되는지 (새로고침 후에도 BEST 유지되는지)
   - New Game(재시작) 버튼이 보드/점수를 초기화하는지
   - 게임 오버 판정이 정상 동작하는지 (더 이상 이동 불가할 때 오버레이가 뜨는지) — 콘솔에서 board를 강제로 채워 테스트해도 좋다
   - 다크모드 토글이 정상 동작하고 값이 유지되는지
   - 모바일 크기(예: 375px, 320px)로 리사이즈했을 때 레이아웃이 깨지지 않는지, 보드가 잘리지 않는지
   - 브라우저 콘솔에 에러가 없는지
4. 코드 자체도 훑어보며 명백한 버그, 예외 상황 미처리(예: 스와이프 threshold 누락, 이벤트 리스너 중복 등), 다크모드 미대응 요소가 없는지 점검한다.
5. **문제를 발견하면 그 자리에서 apps/2048/ 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 3번부터 재검증한다.
6. 모든 검증이 끝나면 `apps/2048/review.md`를 작성한다. 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면, 무엇을 어떻게 고쳤는지)
   - 최종 결론: 정상 배포 가능한지 여부
7. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
