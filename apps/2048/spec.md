# 2048 게임 구현 계획 (spec.md)

## 1. 개요

방향키(↑↓←→) 또는 모바일 스와이프로 4x4 격자 위의 숫자 타일을 밀어 움직이고, 같은 숫자의 타일끼리 만나면 합쳐지는 퍼즐 게임이다. 타일을 밀 때마다 빈 칸 중 하나에 새로운 타일(2 또는 4)이 생성되며, 합쳐질 때마다 점수가 올라간다. 2048 타일을 만들면 승리 안내를 띄우고, 더 이상 움직이거나 합칠 수 있는 칸이 없으면 게임 오버 처리한다. 순수 HTML/CSS/JavaScript로만 구현하며, 블로그 프로젝트의 다른 파일과는 독립적으로 `/apps/2048/` 폴더 안에서 완결되는 정적 웹앱으로 만든다.

## 2. 파일 구조

```
/apps/2048/
  index.html   진입점. 마크업 구조(헤더, 점수판, 보드, 버튼, 안내 오버레이)와 css/js 로드
  style.css    레이아웃, 타일 색상, 다크모드, 반응형 스타일
  game.js      게임 상태, 이동/병합 로직, 입력 처리, 렌더링, localStorage 연동
```

- 이미지/폰트 등 외부 리소스는 사용하지 않는다 (숫자와 색상만으로 타일 표현).
- CDN 라이브러리도 사용하지 않는다 (규모상 불필요).

## 3. 핵심 로직 설계

### 3.1 보드 데이터 구조

- `board`: 4x4 2차원 배열 (`board[row][col]`), 값은 `0`(빈 칸) 또는 2의 거듭제곱 숫자(2, 4, 8, ...).
- 게임 상태 변수:
  - `board` — 현재 보드
  - `score` — 현재 점수
  - `best` — 최고 점수 (localStorage에서 로드)
  - `isGameOver` — 게임 오버 여부
  - `hasWon` — 2048 달성 후 승리 안내를 이미 띄웠는지 여부 (승리 후에도 계속 플레이 가능해야 하므로 별도 플래그로 관리)

### 3.2 타일 이동/병합 알고리즘

네 방향(상/하/좌/우) 모두 "왼쪽으로 밀기" 로직 하나를 축으로 재사용한다.

1. 방향에 따라 보드를 회전/전치하여 항상 "왼쪽으로 미는" 상황으로 통일한다.
   - 왼쪽: 그대로
   - 오른쪽: 각 행을 뒤집기(reverse) → 왼쪽 로직 적용 → 다시 뒤집기
   - 위: 보드를 전치(transpose) → 왼쪽 로직 적용 → 다시 전치
   - 아래: 전치 → 각 행 뒤집기 → 왼쪽 로직 적용 → 뒤집기 → 전치
2. 각 행에 대해 "한 줄 처리" 함수를 적용한다:
   - 0이 아닌 값들만 순서대로 추출(compact).
   - 왼쪽부터 인접한 두 값이 같으면 병합(하나로 합치고 값은 2배, 병합된 타일은 같은 턴에 다시 병합되지 않도록 인덱스를 건너뜀). 병합된 값을 `score`에 더한다.
   - 병합 후 다시 compact하여 남은 칸을 0으로 채운다.
3. 이동 전/후 보드를 비교하여 변화가 있었는지(`moved` boolean) 판정한다. 변화가 없으면 새 타일을 생성하지 않는다(무효 입력 처리).
4. 이동이 유효했다면:
   - 새 타일 생성
   - 점수 갱신 및 최고 점수 갱신/저장
   - 2048 타일 등장 및 아직 승리 안내를 안 띄웠다면 승리 오버레이 표시
   - 더 이상 이동 불가 상태인지 검사하여 게임 오버 처리

### 3.3 새 타일 생성 규칙

- 매 유효한 이동 후, 빈 칸(`value === 0`) 목록을 수집한다.
- 빈 칸이 없으면 생성하지 않는다(게임 오버 판정으로 이어짐).
- 빈 칸 중 무작위 위치 하나를 선택한다.
- 값은 90% 확률로 `2`, 10% 확률로 `4`를 부여한다.
- 게임 시작 시에는 이 과정을 두 번 수행하여 초기 타일 2개를 배치한다.

### 3.4 점수 계산 방식

- 두 타일이 병합될 때마다 병합 결과 값(예: 2+2=4 → 4점 추가)을 `score`에 누적한다.
- `score`가 `best`보다 커지면 즉시 `best`를 갱신하고 localStorage에 저장한다.
- 재시작 시 `score`는 0으로 초기화되지만 `best`는 유지된다.

### 3.5 게임 오버/승리 판정 조건

- **승리**: 보드 내 어떤 타일이든 값이 2048 이상이 되는 순간, 아직 승리 안내를 표시하지 않았다면("You Win" 오버레이) 표시하고 `hasWon = true`로 설정. 사용자는 오버레이에서 "계속하기"를 선택해 계속 플레이하거나 재시작할 수 있다.
- **게임 오버**: 다음 두 조건을 모두 만족할 때
  - 빈 칸이 하나도 없고,
  - 인접한(상하좌우) 어떤 두 타일도 같은 값을 가지지 않아 더 이상 병합이 불가능할 때
  - 이 경우 "Game Over" 오버레이와 재시작 버튼을 표시한다.

## 4. 입력 처리

### 4.1 키보드

- `document`에 `keydown` 리스너를 등록.
- `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` 키 코드에 대해 `event.preventDefault()`로 페이지 스크롤을 막고 해당 방향의 이동 함수를 호출.
- 게임 오버 상태에서는 이동 입력을 무시한다.

### 4.2 모바일 터치/스와이프

- 보드 요소에 `touchstart`, `touchmove`(스크롤 방지용 `preventDefault` 포함), `touchend` 리스너를 등록.
- `touchstart` 시 시작 좌표(x, y) 기록, `touchend` 시 종료 좌표와의 차이(dx, dy) 계산.
- 스와이프로 인식할 최소 이동 거리(threshold, 예: 20~30px) 이상일 때만 방향 판정.
- `abs(dx) > abs(dy)`이면 좌/우, 아니면 상/하 방향으로 판정하여 동일한 이동 함수 호출.

## 5. UI/디자인

### 5.1 레이아웃 구성

- 상단: 게임 제목, 오른쪽에 점수판 2칸(SCORE / BEST)을 카드 형태로 배치.
- 그 아래: 재시작(New Game) 버튼과 다크모드 토글 버튼.
- 중앙: 4x4 보드 (CSS Grid 사용, `grid-template-columns/rows: repeat(4, 1fr)`), 타일 사이 간격은 grid gap으로 처리.
- 보드 위에 조건부로 표시되는 오버레이(게임 오버 / 승리 메시지 + 버튼), `position: absolute`로 보드 위에 겹쳐 표시.
- 보드 하단 또는 상단에 간단한 조작 안내 문구("방향키 또는 스와이프로 이동").

### 5.2 다크모드 대응

- 색상 값은 모두 CSS 변수(`--bg`, `--board-bg`, `--tile-empty`, `--text-color`, `--card-bg` 등)로 `:root`에 정의.
- `@media (prefers-color-scheme: dark)`로 다크 팔레트 자동 적용.
- 우측 상단(또는 버튼 영역)에 수동 토글 버튼을 두고, 클릭 시 `document.documentElement`에 `data-theme="dark"` / `data-theme="light"` 속성을 설정하여 CSS 변수 오버라이드. 선택값은 localStorage에 저장하여 재방문 시 유지.

### 5.3 타일 색상 구성

- 숫자 값을 key로 하는 색상 매핑 객체(예: `{2: '#eee4da', 4: '#ede0c8', 8: '#f2b179', ..., 2048: '#edc22e'}`)를 CSS 클래스(`tile-2`, `tile-4`, ...) 또는 인라인 스타일로 적용.
- 매핑에 없는 큰 값(4096 이상 등)은 공통 폴백 색상 하나로 처리.
- 숫자가 커질수록 글자 크기를 약간 줄여 4자리 숫자도 타일 안에 들어가도록 처리(`font-size`를 자릿수에 따라 클래스 분기 또는 `clamp()` 사용).
- 다크모드에서는 타일 색상 자체는 유지하되 보드/배경/텍스트 대비를 다크 팔레트에 맞게 조정.

### 5.4 모바일 반응형 고려사항

- 보드 크기는 뷰포트 너비 기준 가변 크기(`min(90vw, 420px)` 등)로 설정하여 작은 화면에서도 4개 열이 잘리지 않도록 함.
- 타일 폰트 크기도 보드 크기에 비례하도록 상대 단위(`vw` 또는 CSS `clamp()`) 사용 고려.
- 점수판/버튼 영역은 좁은 화면에서 세로로 쌓이거나 줄바꿈되도록 flexbox `flex-wrap` 적용.
- 터치 조작 시 보드 영역 스와이프가 페이지 스크롤과 충돌하지 않도록 `touch-action: none` 또는 `preventDefault` 처리.
- 최소 지원 폭 320px 기준으로 레이아웃 확인.

## 6. 로컬 저장 (localStorage)

- Key: `2048-best-score` (예시, game.js 내 상수로 정의) — 최고 점수(숫자)를 저장.
- Key: `2048-theme` (예시) — 사용자가 수동으로 선택한 다크/라이트 모드 값을 저장 (`"dark"` / `"light"`), 값이 없으면 `prefers-color-scheme`을 따름.
- 페이지 로드 시 `localStorage.getItem`으로 두 값을 읽어 초기 상태에 반영하고, 값이 없거나 파싱 불가하면 기본값(best=0, 시스템 테마)으로 폴백.
- 게임 진행 중 board/score 자체는 저장하지 않는다(새로고침 시 새 게임으로 시작, best score만 유지). 필요 시 향후 확장 여지로 남겨둔다.

## 7. 작업 순서 (Build 단계 체크리스트)

1. `apps/2048/index.html` 뼈대 작성: 제목, 점수판(SCORE/BEST) 마크업, New Game 버튼, 다크모드 토글 버튼, 4x4 보드 컨테이너, 오버레이 요소, css/js 링크.
2. `apps/2048/style.css`에 기본 레이아웃(플렉스/그리드) 및 라이트 모드 CSS 변수 작성.
3. 다크모드 CSS 변수 및 `prefers-color-scheme`/`data-theme` 대응 스타일 추가.
4. `apps/2048/game.js`에 보드 초기화 함수와 4x4 배열 렌더링 함수(DOM에 타일 그리기) 작성, 정적 보드로 우선 화면에 표시.
5. 타일 색상 매핑 및 숫자별 스타일(`tile-N` 클래스) 적용, 큰 숫자 폰트 축소 처리.
6. 새 타일 생성 로직(빈 칸 탐색, 2/4 확률 배치) 구현 및 게임 시작 시 타일 2개 배치.
7. "왼쪽으로 밀기" 한 줄 처리 함수(compact + merge) 구현 및 단위 동작 확인.
8. 회전/전치를 이용한 4방향 이동 함수 구현, `moved` 여부 판정 로직 포함.
9. 키보드 방향키 입력 리스너 연결, 유효 이동 시에만 새 타일 생성 및 재렌더링.
10. 점수 계산(병합 시 누적) 및 점수판 DOM 갱신 로직 구현.
11. localStorage 연동: best score 로드/저장, 갱신 시 즉시 반영.
12. 게임 오버 판정 함수 구현 및 오버레이 표시, 재시작 버튼 동작(보드/점수 초기화) 구현.
13. 2048 달성 승리 판정 및 승리 오버레이("계속하기"/재시작 선택지) 구현.
14. 모바일 터치 스와이프 이벤트(touchstart/touchmove/touchend) 구현 및 방향키 로직과 연결.
15. 다크모드 수동 토글 버튼 동작 구현 및 localStorage 저장/복원 연결.
16. 반응형 스타일 점검: 좁은 화면(320~420px)에서 보드/점수판/버튼 레이아웃 확인 및 조정.
17. 라이트/다크 모드 각각에서 전체 화면 육안 점검, 데스크톱 키보드 조작과 모바일 스와이프 조작 모두 수동 테스트.
18. 엣지 케이스 점검: 보드가 꽉 찼지만 이동 가능한 경우, 이동해도 변화 없는 입력(무시되는지), 재시작 후 best score 유지 여부.
