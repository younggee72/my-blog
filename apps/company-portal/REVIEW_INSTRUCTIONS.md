# Review 서브에이전트 지침 — 사내 포털 개편(대외 홍보 랜딩 + 비밀번호 잠금)

## 역할
너는 이 프로젝트(마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Review 단계** 서브에이전트다.
Build 단계에서 개편된 사내 포털(`apps/company-portal/`)을 검증하는 것이 임무다. 너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

## 범위 제한
- 검증 대상은 `apps/company-portal/` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/company-portal/` 폴더 안의 파일만 수정**한다. 다른 apps/*/(특히 `apps/settlement/`, `apps/vehicle-fleet/`)와 블로그 본체 파일은 절대 건드리지 않는다.
- 최종 산출물로 `apps/company-portal/review.md`를 **덮어써서** 새로 작성한다(기존 review.md는 1~6장 기준 검증 결과이므로, 이번엔 7장 개편분까지 포함한 전체 재검증 결과로 갱신).

## 참고 문서
- `apps/company-portal/spec.md` — 1~7장 전체(특히 7장: 공개 랜딩 + 비밀번호 잠금 설계)
- `apps/company-portal/index.html`, `style.css`, `portal.js`, `app.js` — 검증 대상

## 검증 절차
1. spec.md 7장을 읽고 이번 개편 요구사항을 파악한다(1~6장은 기존 review.md에서 이미 검증된 내용이니 이번엔 "회귀 여부" 위주로 재확인).
2. 코드를 읽고 spec.md 7장과 대조한다:
   - 비밀번호 해시가 코드에 평문 "7200"으로 노출되어 있지 않은지(`grep`으로 "7200" 문자열이 코드에 없는지 확인, 해시값만 있어야 함)
   - `sessionStorage`를 사용하는지(요구사항상 `localStorage` 아님)
   - 보안 한계 고지 문구가 화면(모달 또는 안내박스)에 실제로 보이는지
3. 브라우저 프리뷰 도구로 `apps/company-portal/index.html`을 **정적 서버로 띄워서**(file://로 직접 열지 말 것 — `crypto.subtle`이 file:// 프로토콜에서 제한될 수 있음) 실제 동작을 확인한다:
   - 처음 접속 시 공개 랜딩(히어로/사업분야/시공실적/연락처)만 보이고, 업무 도구·진행중인 현장 섹션은 보이지 않는지
   - "🔒 직원 전용 업무 시스템" 버튼 클릭 → 비밀번호 모달이 뜨는지
   - 틀린 비밀번호(예: "0000", "1234") 입력 시 에러 표시되고 내부 영역이 열리지 않는지
   - 올바른 비밀번호("7200") 입력 시 내부 영역(허브 카드 + 진행중인 현장)이 정상적으로 나타나는지
   - 같은 탭에서 새로고침해도 다시 잠기지 않는지(세션 유지), 새 탭에서 같은 URL을 열면 다시 잠긴 상태로 시작하는지(sessionStorage 특성 — 시크릿/새 탭으로 확인)
   - "다시 잠그기" 버튼 클릭 시 즉시 재잠금되는지
   - 모바일 뷰(375px)에서 비밀번호 입력 필드가 숫자 키패드(`inputmode="numeric"`)로 뜨는지, 레이아웃이 깨지지 않는지
   - 다크모드 토글 시 공개 랜딩과 내부 영역 모두 팔레트가 정상 전환되는지
   - 공개 랜딩의 플레이스홀더 문구마다 "예시 텍스트이니 교체하라"는 안내가 실제로 보이는지
4. **회귀 확인(매우 중요)**: 비밀번호 통과 후 내부 영역에서 기존 1~6장 기능이 전혀 깨지지 않았는지 반드시 확인한다 — 현장 등록/수정/삭제, 상세 모달에서 금액 정보 노출, vehicle-fleet 차량 목록 읽기 전용 연동(있을 때/없을 때), 허브 카드가 `apps/settlement/index.html`·`apps/vehicle-fleet/index.html`로 정상 이동하는지.
5. 코드 정적 점검: `innerHTML`로 사용자 입력을 삽입하는 곳에 XSS 방어(`escapeHtml` 등)가 유지되고 있는지, 이번 개편으로 새로 추가된 코드에도 같은 원칙이 적용됐는지. `git status --porcelain apps/settlement apps/vehicle-fleet`로 두 앱이 이번 Review 작업 중에도 변경되지 않았는지 최종 확인.
6. **문제를 발견하면 그 자리에서 `apps/company-portal/` 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 2~5번부터 재검증한다.
7. 모든 검증이 끝나면 `apps/company-portal/review.md`를 새로 작성한다(1~6장 결과도 이번에 재확인한 내용으로 간단히 포함하고, 7장 개편분 검증 결과를 중심으로 작성). 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면)
   - 최종 결론: 정상 배포 가능한지 여부
8. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
