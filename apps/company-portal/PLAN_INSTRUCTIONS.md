# Plan 서브에이전트 지침 — 사내 포털 개편(대외 홍보 랜딩 + 비밀번호 잠금)

## 역할
너는 이 프로젝트(마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Plan 단계** 서브에이전트다.
이미 구현되어 있는 `apps/company-portal/`(spec.md, review.md 포함)을 **개편**하는 계획을 세워, `apps/company-portal/spec.md`에 새 섹션으로 추가하는 것이 임무다.
**코드를 작성하지 마라.** 계획 문서만 수정한다. 기존 spec.md의 1~6장 내용은 그대로 두고, 이번 개편 내용을 이어서 새로운 장(예: 7장)으로 추가해라(기존 내용을 지우거나 덮어쓰지 말 것).

## 먼저 읽어야 할 것
- `apps/company-portal/spec.md` — 기존 계획(허브 카드 + 진행중인 현장 관리)
- `apps/company-portal/review.md` — 기존 구현 검증 결과
- `apps/company-portal/index.html`, `style.css`, `portal.js`, `app.js` — 기존 구현 코드(개편 시 어떤 부분을 고쳐야 할지 파악하기 위해 읽어라)

## 프로젝트 제약 조건
- 마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용, 빌드 도구/번들러 없음.
- 모든 웹앱은 `/apps/{앱이름}/` 폴더 안에 자체 완결된다.
- 외부 라이브러리 사용을 최소화한다.
- 모바일에서도 사용할 수 있어야 한다.
- 사이트 색상 팔레트(`/css/style.css`의 CSS 변수)를 따른다.
- 사용법 안내 문구를 포함한다.
- `apps/company-portal/` 밖의 파일(다른 앱, 블로그 본체)은 건드리지 않는다.

## 배경
이 회사 홈페이지(`apps/company-portal/`)는 이제 **두 가지 목적**을 함께 가진다:
1. **대외 홍보**: 회사를 모르는 외부인이 링크로 들어와도 볼 수 있는 공개 소개 페이지 (이미 GitHub Pages로 공개 배포됨: `https://younggee72.github.io/my-blog/apps/company-portal/index.html`)
2. **사내 업무 도구**: 기존에 구현된 허브 카드(현장정산서/법인차량관리 링크)와 "진행중인 현장" 관리(계약금액·기성고 등 민감정보 포함)는 외부인에게 노출되면 안 되는 내부 전용 기능

사용자 요청 원문: "전체 공개로 가고, 이후 외부공개하지 말아야 할 사항들은 접촉 비번설정하던지 해서 비공개 사항을 만들지... 그리고 이 홈페이지는 대외적으로 회사알림 목적도 있어. 지금은 그냥 만들어 보는데, 대외적으로 홍보 역할기능도 추가할 계획이야." 확정된 비밀번호: **"7200"**

## 요구사항

### 1. 페이지 구조를 두 영역으로 재편
- **공개 영역(기본으로 즉시 보임, 비밀번호 불필요)**: 대외 홍보용 랜딩 콘텐츠.
  - 회사명("주식회사 지천건설")을 크게 노출하는 히어로 영역, 슬로건/한줄소개(플레이스홀더 텍스트, 예: "믿을 수 있는 시공, 지천건설이 만듭니다" 등 — 실제 문구는 나중에 교체한다는 안내와 함께).
  - 사업분야 소개 카드 몇 개(플레이스홀더, 예: "토목", "건축", "중장비 임대" 등 — 실제 내용으로 교체 필요 표시).
  - 시공실적/포트폴리오 섹션(플레이스홀더 카드 2~3개, 실제 사진/내용 없이 "추후 시공 사례 추가 예정" 자리로 남겨도 됨).
  - 연락처 섹션(플레이스홀더: 주소/전화/이메일 형태만 잡아두고 실제 값은 "예시입니다. 실제 정보로 수정하세요" 안내).
  - **모든 플레이스홀더 텍스트는 화면에서 눈에 띄게 "예시 텍스트이니 실제 내용으로 교체하세요"라고 안내한다**(다른 앱들의 시드데이터 안내 패턴과 동일).
- **내부 영역(비밀번호 입력 후에만 보임)**: 기존에 이미 구현된 "업무 도구"(허브 카드 3장)와 "진행중인 현장" 섹션 전체(등록/수정/삭제, 상세보기 등 기존 기능 그대로 유지). 공개 영역 하단 또는 별도 지점에 "🔒 직원 전용 업무 시스템" 버튼을 두고, 클릭하면 비밀번호 입력 프롬프트/모달이 뜬다.

### 2. 비밀번호 잠금 방식
- 비밀번호는 **"7200"**으로 확정되었다. 이 값을 코드에 평문으로 그대로 두지 말고, **SHA-256 해시값만 코드에 저장**하고, 사용자가 입력한 값을 같은 방식으로 해시해 비교하는 방식으로 설계한다(완벽한 보안은 아니지만 평문 노출은 피한다 — 이 트레이드오프를 spec.md에 명시).
- 통과하면 내부 영역이 화면에 나타난다(잠금 해제 상태를 `sessionStorage` 또는 `localStorage`에 플래그로 저장해, 같은 브라우저에서는 새로고침해도 다시 묻지 않게 할지 여부를 판단해서 설계 — 세션 동안만 유지할지, 브라우저에 계속 저장할지 spec.md에서 결론을 내려라. 사용 편의성과 "다음에 열 때 또 물어봐야 안전하지 않을까"의 트레이드오프를 짧게 설명).
- 이 잠금은 **클라이언트 사이드 수준의 가림막**이며 완전한 보안이 아니라는 점(개발자도구로 우회 가능함)을 spec.md와 화면 안내 문구 양쪽에 명시한다. 사용자도 이미 이 한계를 인지하고 동의했다.
- 비밀번호 입력 UI는 모바일에서도 쓰기 편해야 한다(숫자 키패드 `inputmode="numeric"` 등 고려).

### 3. 기존 기능과의 관계
- 기존 "진행중인 현장" 데이터/로직(4개 영역: 기본정보/진행상태/금액/투입차량), vehicle-fleet 읽기 전용 연동, localStorage 키 등은 **그대로 유지**한다. 이번 개편은 "어떤 화면을 먼저 보여주고, 무엇을 잠글지"에 대한 레이아웃/접근제어 변경이다.
- 기존 사용법 안내 문구도 유지하되, 새로 추가되는 공개 영역/잠금 방식에 대한 안내를 보강한다.

## 산출물
`apps/company-portal/spec.md`에 새 장(7장, "공개 랜딩 페이지 및 접근 제어")을 추가한다. 포함할 내용:

1. **개편 개요**: 공개 영역과 내부 영역을 나누는 이유와 전체 구조 요약.
2. **공개 랜딩 콘텐츠 설계**: 어떤 섹션들을 넣을지, 각 섹션의 플레이스홀더 문구 초안(실제로 화면에 넣을 예시 문구를 구체적으로 작성 — Build 단계에서 그대로 가져다 쓸 수 있게).
3. **비밀번호 잠금 설계**: 해시 방식, 잠금 해제 상태 저장 방식과 그 이유, UI 흐름(버튼 → 입력 프롬프트/모달 → 통과/실패 처리 → 내부 영역 표시), 보안 한계 고지 문구.
4. **파일 변경 범위**: `index.html`/`style.css`/`portal.js`/`app.js` 중 어디에 무엇을 추가/수정해야 하는지.
5. **작업 순서(체크리스트)**: Build 단계에서 순서대로 구현할 수 있도록 번호가 매겨진 단계별 작업 목록.

계획을 다 작성했으면 `apps/company-portal/spec.md`에 추가 저장하고, 무엇을 추가했는지 간단히 요약해서 보고하라 (300자 이내).
