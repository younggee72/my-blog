# Plan 서브에이전트 지침 — 현장정산서 자동화 도구 (settlement)

## 역할
너는 이 프로젝트(마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Plan 단계** 서브에이전트다.
아래 요구사항을 바탕으로 구현 계획을 세우고, `apps/settlement/spec.md` 파일로 저장하는 것이 유일한 임무다.
**코드를 작성하지 마라.** 계획 문서만 작성한다.

## 프로젝트 제약 조건
- 순수 HTML, CSS, JavaScript만 사용. 빌드 도구/번들러 없음.
- 외부 라이브러리 사용은 최소화하되 CDN은 허용됨 (이 앱은 엑셀 내보내기를 위해 CDN의 SheetJS(xlsx.js)를 사용해도 됨).
- 모든 웹앱은 `/apps/{앱이름}/` 폴더 안에 자체 완결된다.
- 모바일에서도 사용할 수 있어야 한다.
- 모든 웹앱은 블로그의 색상 팔레트를 따른다 (`/css/style.css`의 CSS 변수 참조).
- 웹앱에 사용법 안내 문구를 반드시 포함한다.

## 웹앱 공통 규칙
- 모든 웹앱은 `apps/settlement/` 폴더 안에 자체 완결되어야 한다. 프로젝트의 다른 파일(`index.html`, `post.html`, `/css/`, `/js/`, `/posts/`, 다른 `apps/*/` 폴더 — 특히 `apps/2048/`, `apps/pixel-art/`)은 건드리지 않는다.
- 외부 라이브러리 사용을 최소화한다. 단, 엑셀(.xlsx) 내보내기 기능을 위해 SheetJS(xlsx.js) 같은 CDN 라이브러리는 사용해도 된다.
- 모바일에서도 사용 가능해야 한다(터치 입력, 넓은 표의 가로 스크롤 등 고려).
- 다크 모드를 지원해야 한다 (`prefers-color-scheme` 자동 대응 + 수동 토글, `[data-theme]` 속성과 localStorage로 상태 저장하는 이 프로젝트의 기존 패턴을 따를 것 — `js/theme.js`, `css/style.css`를 참고해서 같은 메커니즘을 앱 내부에서도 재사용).
- 사이트의 색상 팔레트를 따라야 한다. `/css/style.css`의 `:root` / `[data-theme="dark"]` CSS 변수(`--color-bg`, `--color-text`, `--color-accent` 등 실제 정의된 변수명을 확인해서 그대로 참조)를 사용할 것.
- 화면 안에 사용법 안내 문구를 반드시 포함해야 한다(별도 도움말 페이지가 아니라, 앱을 열자마자 보이는 짧은 안내).

## 사용자 요청
"실제 사용 중인 건설 현장정산서 엑셀 양식을 분석해서, 동일한 항목과 계산 로직을 그대로 재현하는 웹앱을 만들어줘. 공개 포트폴리오 카드로 블로그에 올릴 것이므로, 실제 회사/거래처 데이터는 절대 포함하지 말고 완전히 빈 템플릿 상태의 범용 계산기로 만들어줘."

## 원본 엑셀 양식 분석 결과 (반드시 이 구조를 그대로 반영)

### 상단 기본 정보
- 공사명 (텍스트 입력)
- 공급가액 (숫자 입력)
- 부가세 = 공급가액 × 10% (자동 계산, 읽기 전용 표시)
- 합계(계약금액) = 공급가액 + 부가세 (자동 계산)

### 지출 내역 — 3개의 독립된 표. 각 표는 행 추가/삭제가 가능해야 하며, 입력값이 바뀔 때마다 소계가 즉시 재계산되어야 한다.

**1. 외주·자재비**
컬럼: 순번(자동번호) · 공종 · 발행일 · 거래처 · 사업자등록번호 · 공급가액(입력) · 부가세(=공급가액×10%, 자동) · 합계(=공급가액+부가세, 자동) · 전자세금계산서 여부(체크박스 또는 선택) · 결제은행 · 결제일 · 결제금액(입력, 기본값은 합계와 동일하게 두되 수정 가능) · 잔액(=합계-결제금액, 자동) · 계좌정보(은행명/계좌번호/예금주) · 연락처 · 비고
소계: 공급가액 합, 부가세 합, 합계 합 (자동)

**2. 노무비**
컬럼: 순번(자동번호) · 발행일 · 인부명 · 항목(예: "N월노무비", 텍스트) · 공급가액(일당, 입력) · 원천세(입력) · 합계(=공급가액-원천세, 자동)
소계: 공급가액 합, 원천세 합, 합계 합 (자동)

**3. 기타 협회 및 보증서**
컬럼: 순번(자동번호) · 발행일 · 거래처(예: 근로복지공단/국세청/구청) · 항목(예: 고용보험료/소득세/지방세) · 공급가액(입력) · 부가세(입력 가능, 원본에서는 항목에 따라 0이거나 공급가액×10%인 경우가 섞여 있었으므로 자동계산 대신 입력 필드로 두되 "공급가액×10% 채우기" 같은 보조 버튼은 선택사항) · 합계(=공급가액+부가세, 자동)
소계: 공급가액 합, 부가세 합, 합계 합 (자동)

### 하단 정산 요약 (모두 자동 계산, 위 입력값이 바뀔 때마다 갱신)

**요약 A (세금계산서 대비 지출 비교)**
- 세금계산서발행금액 = 상단의 공급가액 / 부가세 / 합계
- 매입자료금액 = 표1(외주·자재비) 소계
- 노무비 = 표2 소계
- 기타보증서 = 표3 소계
- 잔여마진 = 세금계산서발행금액 − 매입자료금액 − 노무비 − 기타보증서 (공급가액/부가세/합계 각 열별로)

**요약 B (수익 정산표)**
- 공급가액 = 상단 공급가액
- 기술료 = 공급가액 × 5% (주석: "공급가액 × 5%")
- 경비 = 표3(기타 협회 및 보증서) 소계 공급가액 (주석: "건설공제조합/전력 및 수도광열비 등")
- 매입액 = 표1(외주·자재비) 소계 공급가액
- 노무비 = 표2(노무비) 소계 합계
- 잔여금액 = 공급가액 − 기술료 − 경비 − 매입액 − 노무비

**계좌 정보란**: 은행명, 계좌번호를 표시/입력할 수 있는 간단한 필드 (정산금 입금 계좌 표시용)

이 계산 로직들은 원본 엑셀 수식을 그대로 옮긴 것이다. 임의로 로직을 바꾸지 말 것.

## 기능 요구사항 (사용자 확정 — 반드시 준수)
- **저장**: 모든 입력값(상단 정보 + 3개 표의 모든 행)을 `localStorage`에 자동 저장하여 새로고침해도 유지되어야 한다. 페이지 로드 시 저장된 값이 있으면 복원한다.
- **엑셀 내보내기**: "엑셀로 내보내기" 버튼을 눌러 현재 입력된 데이터를 원본과 유사한 구조(상단 정보, 3개 표, 하단 정산 요약)로 정리한 `.xlsx` 파일을 다운로드할 수 있어야 한다. CDN의 SheetJS(xlsx.full.min.js)를 사용할 것.
- **단일 정산서만 관리**: 여러 현장을 저장/전환하는 기능은 만들지 않는다. "초기화" 버튼을 눌러 현재 데이터를 모두 지우고 빈 템플릿으로 되돌릴 수 있어야 한다 (실행 전 확인 대화상자 필요).
- **모바일 대응**: 표가 넓으므로 각 표를 가로 스크롤 가능한 컨테이너로 감싸는 등 반응형을 고려한다.
- **사용법 안내**: 앱 상단에 이 도구가 무엇이고 어떻게 쓰는지 짧게 설명하는 안내 문구를 포함한다.
- **초기 데이터**: 실제 회사명/거래처/금액은 절대 포함하지 않는다. 빈 값 또는 플레이스홀더(예: "거래처명 입력")만 사용한다.

## 산출물
`apps/settlement/spec.md` 파일 하나를 작성한다. 내용에는 다음이 포함되어야 한다:

1. **개요**: 앱 설명 한두 문단.
2. **파일 구조**: `apps/settlement/` 안에 만들 파일 목록과 각 파일의 역할.
3. **핵심 로직 설계**: 데이터 구조(JS 객체/배열 형태 구체적으로), 3개 표의 행 추가/삭제/재계산 로직, 정산 요약 계산 로직, localStorage 저장 방식(키 이름, 저장 시점), 엑셀 내보내기 시 시트 레이아웃 설계.
4. **입력 처리**: 표 행 추가/삭제 UI, 숫자 입력 포맷(천단위 콤마 등), 모바일 터치/스크롤 충돌 방지 방법.
5. **UI/디자인**: 레이아웃 구성(상단 정보 → 3개 표 → 정산 요약 → 액션 버튼), 다크모드 대응, 참조할 CSS 변수명, 반응형(가로 스크롤 표) 처리, 사용법 안내 문구 배치 위치.
6. **작업 순서(체크리스트)**: Build 단계에서 순서대로 구현할 수 있도록 번호가 매겨진 단계별 작업 목록. 각 단계는 한 번에 검증 가능한 크기로 쪼갠다.

계획을 다 작성했으면 `apps/settlement/spec.md`로 저장하고, 무엇을 작성했는지 간단히 요약해서 보고하라 (300자 이내).
