# Plan 서브에이전트 지침 — 현장정산서: 계산서 자동인식 + 공사명별 자동생성 기능 추가

## 역할
너는 이 프로젝트(마크다운 블로그 + 미니 웹앱 포트폴리오)의 **Plan 단계** 서브에이전트다.
이번 작업은 새 앱이 아니라 **이미 만들어져 있는 `apps/settlement/` (현장정산서) 앱에 기능을 추가**하는 것이다.
아래 요구사항을 바탕으로 구현 계획을 세우고, `apps/settlement/spec-v2-invoice.md` 파일로 저장하는 것이 유일한 임무다.
**코드를 작성하지 마라.** 계획 문서만 작성한다.

## 시작 전 필수: 기존 코드 읽기
계획을 세우기 전에 반드시 아래 파일을 전부 읽어라. 기존 상태 모델, localStorage 키, 렌더링 패턴, 폴더 연결(File System Access API) 구현, 엑셀 내보내기(ExcelJS) 구현을 정확히 이해한 뒤에 그 패턴을 그대로 확장해야 한다. 기존 구조와 충돌하거나 중복되는 새 구조를 만들지 마라.
- `apps/settlement/index.html`
- `apps/settlement/settlement.js`
- `apps/settlement/style.css`
- `apps/settlement/spec.md` (기존 설계 문서, 참고용)

## 프로젝트 제약 조건
- 순수 정적 HTML/CSS/JS 블로그+미니웹앱 포트폴리오. 빌드 도구/번들러 없음.
- 백엔드 서버 없음 — 모든 처리는 브라우저(클라이언트 사이드)에서 이루어져야 한다.
- 외부 라이브러리는 CDN으로 허용되나 최소화한다. 이번 기능에는 PDF 텍스트 추출을 위한 PDF.js, 이미지 OCR을 위한 Tesseract.js 같은 CDN 라이브러리 사용이 필요할 것으로 예상된다 — 이미 이 앱은 ExcelJS를 CDN으로 쓰고 있으니 같은 패턴을 따르면 된다.
- 모바일에서도 사용 가능해야 한다.
- 다크 모드 지원 (`prefers-color-scheme` + `[data-theme]` + localStorage 토글, 기존 앱의 `js/theme.js` 패턴과 동일하게).
- 사이트의 색상 팔레트를 따른다 — `/css/style.css`의 `:root` CSS 변수 그대로 참조.
- 화면 안에 사용법 안내 문구 필수 (기존 앱에 이미 guide-box가 있으니 확장해서 이어간다).

## 웹앱 공통 규칙
- 모든 수정은 `apps/settlement/` 폴더 안에서만 이루어진다. 블로그 본체(`index.html`, `/css/`, `/js/`, `/posts/`, 다른 `apps/*/`)는 건드리지 않는다.

## 사용자 요청 (배경)
사용자는 건설법인을 운영하며, 여러 현장의 세금계산서를 관리하고 현장별 정산서를 만드는 작업을 자동화하고 싶어한다.

## 요구사항

### 1단계 — 계산서 업로드 및 목록 관리
- "계산서" 폴더 개념으로 세금계산서 파일(PDF가 주, 스캔본/스크린샷 이미지도 있음)을 업로드하는 UI
- 업로드하면 아래 컬럼을 가진 목록 테이블에 한 줄씩 추가됨:
  순번 | 발행일 | 거래처 | 공종 | 사업자등록번호 | 공급가액 | 부가세 | 합계 | 공사명
- **자동 인식(파싱)**: 발행일/거래처/사업자등록번호/공급가액/부가세/합계는 계산서 파일에서 자동으로 추출
  - 전자세금계산서 PDF는 내부에 텍스트가 임베드되어 있는 경우가 많다 — PDF.js로 텍스트를 추출한 뒤, 국세청 전자세금계산서 표준 양식의 필드 배치를 참고하여 정규식/패턴 매칭으로 각 필드를 뽑아내는 방식을 설계하라 (완벽할 필요는 없다, 아래 검토 단계가 있음).
  - 스캔본/스크린샷 이미지는 Tesseract.js로 OCR 시도 (한국어 언어팩 필요, 정확도가 낮을 수 있음을 명시).
  - "공종"은 계산서 상에 명시적으로 없을 수 있으니, 품목명/비고 등에서 추정하거나 빈 칸으로 두고 사용자가 채우게 하는 현실적인 방안을 계획에 포함하라.
- **공사명**: 계산서 자체에는 없는 정보이므로 항상 사용자가 직접 입력/선택 (자동 인식 대상 아님)
- **필터**: 공사명 컬럼에 필터 버튼(드롭다운) — 지금까지 입력된 공사명 목록 중 선택하면 그 공사명의 계산서만 표시
- **검토/수정 필수**: 자동 인식된 값은 100% 정확하지 않을 수 있으므로, 목록의 각 셀은 사용자가 클릭해서 직접 수정할 수 있어야 한다 (자동인식 값이 틀렸을 때를 위한 명확한 시각적 표시 — 예: "확인 필요" 배지 — 도 고려하라)
- 업로드된 원본 파일도 함께 보관/조회 가능해야 한다 (기존 앱의 "폴더 연결" 기능을 재사용할 수 있는지 검토 — 이미 File System Access API로 폴더 연결/파일 목록 기능이 구현되어 있으므로 그 패턴을 활용하는 것을 우선 고려하라)

### 2단계 — 공사명별 현장정산서 자동 생성
- 같은 공사명으로 묶인 계산서들을 모아서, 기존 현장정산서 양식(현재 settlement.js의 상태 모델)에 공사명이 자동으로 채워진 정산서를 생성하는 기능
- 계산서의 거래처/공급가액/부가세/합계 정보가 정산서의 협력업체(하도급) 내역 행에 자동으로 채워지는 것이 이상적 — 다만 기존 정산서의 "결제금액/잔액" 로직(결제금액은 사용자가 실제 결제했을 때만 입력, 잔액은 합계와 연동)과 충돌하지 않도록 설계하라. 자동 생성 시 결제금액은 0으로 시작해야 한다 (기존 로직 유지).
- 이미 존재하는 공사명으로 다시 생성을 시도할 때의 동작(기존 정산서에 병합할지, 새로 만들지, 사용자에게 물어볼지)을 계획에 명시하라.

## 산출물
`apps/settlement/spec-v2-invoice.md` 파일 하나를 작성한다. 내용에는 다음이 포함되어야 한다:

1. **개요**: 이 기능 확장이 무엇을 하는지, 기존 앱과 어떻게 통합되는지 한두 문단.
2. **파일 구조**: 새로 만들 파일과 기존 파일 중 수정할 파일 목록, 각각의 역할. (예: 새 화면을 별도 뷰/탭으로 추가할지, 새 HTML 파일로 분리할지 등 UI 구조 결정 포함)
3. **핵심 로직 설계**:
   - 계산서 데이터 상태 구조 (localStorage 키, 데이터 스키마)
   - PDF.js/Tesseract.js를 이용한 자동 인식 파이프라인 (어떤 순서로, 어떤 정규식/휴리스틱으로 필드를 뽑아내는지 구체적으로)
   - 공사명 필터 구현 방식
   - 공사명별 그룹핑 → 정산서 자동 생성 로직 (기존 정산서 상태 모델과의 연동 방식 포함)
4. **입력 처리**: 파일 업로드(드래그앤드롭/버튼), 셀 수정, 필터 조작 — 모바일 터치 고려.
5. **UI/디자인**: 레이아웃(기존 앱에 새 탭/섹션으로 넣을지), 다크모드, 팔레트, 사용법 안내 문구 위치.
6. **한계/주의사항**: OCR/PDF 파싱 정확도의 현실적 한계를 명시하고, 왜 "최종 사용자 검토"가 필수 단계로 설계에 포함되어야 하는지 설명.
7. **작업 순서(체크리스트)**: Build 단계에서 순서대로 구현할 수 있도록 번호가 매겨진 단계별 작업 목록. 각 단계는 한 번에 검증 가능한 크기로 쪼갠다.

계획을 다 작성했으면 `apps/settlement/spec-v2-invoice.md`로 저장하고, 무엇을 작성했는지 간단히 요약해서 보고하라 (400자 이내).
