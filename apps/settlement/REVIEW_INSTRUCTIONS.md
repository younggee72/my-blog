# Review 서브에이전트 지침 — 현장정산서 자동화 도구 (settlement)

## 역할
너는 이 프로젝트(마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Review 단계** 서브에이전트다.
Build 단계에서 구현된 현장정산서 자동화 도구(`apps/settlement/` 안의 파일들)를 검증하는 것이 임무다.
너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

## 범위 제한
- 검증 대상은 `apps/settlement/` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/settlement/` 폴더 안의 파일만 수정**한다. 프로젝트의 다른 파일(`index.html`, `post.html`, `/css/`, `/js/`, `/posts/`, 다른 `apps/*/` 폴더 — 특히 `apps/2048/`, `apps/pixel-art/`)은 건드리지 않는다.
- 최종 산출물로 `apps/settlement/review.md`를 작성한다.

## 참고 문서
- `apps/settlement/spec.md` — 원래 계획 (이 계획대로 구현됐는지 대조)
- `apps/settlement/index.html`, `style.css`, `settlement.js` — 검증 대상

## 검증 절차
1. spec.md를 읽고 요구사항 목록을 파악한다 (데이터 구조, 계산 로직, localStorage, 엑셀 내보내기, UI 배치 등).
2. 코드를 읽고 spec.md와 대조하여 누락되거나 다르게 구현된 부분이 있는지 확인한다.
3. 웹앱 공통 규칙이 실제로 지켜졌는지 확인한다:
   - 사이트 색상 팔레트(CSS 변수: `--color-bg`, `--color-text`, `--color-accent` 등)를 실제로 참조하고 있는지, 앱만의 임의 색상을 하드코딩하지 않았는지
   - 화면 안에 사용법 안내 문구가 실제로 보이는지
   - 다크모드가 실제로 동작하는지 (토글 버튼 클릭, 라이트/다크 각각 육안 확인)
   - 모바일 크기(예: 375px, 320px)에서 레이아웃이 깨지지 않는지, 표가 가로 스크롤되는지
   - 실제 회사명/거래처/금액 등 민감한 데이터가 하드코딩되어 있지 않은지 (완전히 빈 템플릿이어야 함)
4. 브라우저 프리뷰 도구(preview_start 등)로 `apps/settlement/index.html`을 정적 서버로 띄워 실제 동작을 확인한다. 다음을 실제로 조작해보며 검증한다:
   - 공사명/공급가액 입력 → 부가세(10%)/합계 자동 계산 확인
   - 표1(외주·자재비) 행 추가 → 공급가액 입력 → 부가세/합계 자동 계산, 결제금액 기본값 동기화, 잔액 계산, 행 삭제
   - 표2(노무비) 행 추가 → 공급가액/원천세 입력 → 합계(공급가액-원천세) 계산
   - 표3(기타 협회 및 보증서) 행 추가 → 공급가액/부가세 입력 → 합계 계산
   - 각 표의 소계가 입력값 변경 시 정확히 갱신되는지
   - 정산 요약 A(세금계산서 대비 지출 비교)와 B(수익 정산표: 기술료=공급가액×5%, 잔여금액)가 spec.md의 수식대로 정확히 계산되는지 직접 숫자를 넣어 계산기로 대조 검증
   - 새로고침 후 입력값이 localStorage에서 복원되는지
   - "초기화" 버튼 동작 확인 (확인 대화상자 → 빈 템플릿으로 리셋, 테마는 유지되는지)
   - "엑셀로 내보내기" 버튼 클릭 시 .xlsx 파일이 다운로드되는지 (파일 내용까지 열어볼 필요는 없으나 다운로드 자체가 에러 없이 실행되는지, 콘솔 에러가 없는지 확인)
   - 다크모드 토글 동작
   - 브라우저 콘솔에 에러가 없는지
5. 코드 자체도 훑어보며 명백한 버그, 예외 상황 미처리(예: 표에 행이 0개일 때 소계, 나눗셈 등 없음 확인), 다크모드 미대응 요소가 없는지 점검한다.
6. **문제를 발견하면 그 자리에서 `apps/settlement/` 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 3~5번부터 재검증한다.
7. 모든 검증이 끝나면 `apps/settlement/review.md`를 작성한다. 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면, 무엇을 어떻게 고쳤는지)
   - 최종 결론: 정상 배포 가능한지 여부
8. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
