# Plan 서브에이전트 지침 — 현장정산서: 홈택스 목록 엑셀 일괄 불러오기

## 역할
너는 이 프로젝트의 **Plan 단계** 서브에이전트다. 이미 있는 `apps/settlement/` 앱의 계산서함(`invoices.html`/`invoices.js`)에 기능을 추가하는 계획을 세우고 `apps/settlement/spec-v7-hometax.md` 하나로 저장하는 것이 유일한 임무다. **코드를 작성하지 마라.**

## 시작 전 필수: 기존 코드 읽기
- `apps/settlement/invoices.html`, `invoices.js`, `invoices.css`, `shared-utils.js`
- `apps/settlement/spec-v2-invoice.md`, `review-v5-excel.md`, `review-v6-xls.md` (기존 엑셀 경로 설계·검증 기록)
- 필요하면 `settlement.js`의 정산서 상태 모델(표1 외주·자재비 행, projectInfo.supplyAmount)
기존 상태 구조(`settlement-invoices-state`), 행 스키마, 공사명 필터, "공사명으로 정산서 생성" 로직을 그대로 재사용하라. 새 저장소나 중복 구조를 만들지 마라.

## 제약
- 정적 사이트(GitHub Pages), 서버 없음, 모든 처리는 브라우저에서. 공동인증서·비밀번호·API 키 등 민감정보를 다루거나 저장하지 않는다.
- 엑셀 읽기는 이미 쓰는 ExcelJS(.xlsx)/SheetJS(.xls) CDN을 재사용. 새 라이브러리 추가 금지.
- 수정 범위는 `apps/settlement/` 안. 모바일 사용 가능, 다크모드·사용법 안내 유지.

## 사용자 요청 (배경)
사용자(건설법인)는 홈택스에서 발행·수취되는 매출·매입 전자세금계산서를 정산서로 자동으로 가져오고 싶다. 홈택스는 직접 API가 없으므로, 홈택스 "전자(세금)계산서 → 목록조회(매출/매입)" 화면의 **엑셀 내려받기** 파일을 계산서함에 한 번 올리면 수십 건이 한꺼번에 목록 행으로 들어오게 한다. 지금 계산서함은 파일 1개 = 계산서 1건 구조다.

## 요구사항
1. **홈택스 목록 엑셀 자동 판별**: 업로드된 .xlsx/.xls가 단건 계산서인지 홈택스 목록인지 판별. 목록 파일은 상단에 제목/조회조건 몇 줄이 있고, 그 아래 헤더 행에 대략 다음 열들이 있다(실제 파일로 확인 못 했으니 열 순서가 아니라 **헤더 이름으로** 찾고, 공백·줄바꿈 차이를 허용하도록 설계): 작성일자, 승인번호, 발급일자, 전송일자, 공급자사업자등록번호, 종사업장번호, 상호, 대표자명, 주소, 공급받는자사업자등록번호, 종사업장번호, 상호, 대표자명, 주소, 합계금액, 공급가액, 세액, 전자세금계산서분류, 전자세금계산서종류, 발급유형, 비고, 영수/청구 구분, 이메일들, 품목일자, 품목명, 품목규격, 품목수량, 품목단가, 품목공급가액, 품목세액, 품목비고. "상호" 등이 공급자/공급받는자로 두 번 나오므로 앞뒤 위치(각 사업자등록번호 열 뒤)로 구분하는 방법을 설계하라. 판별 기준은 헤더 행에 "승인번호"와 "공급가액"이 함께 있는 것 등으로.
2. **매출/매입 구분**: 시트 제목이나 상단 셀에 "매출"/"매입"이 있으면 그걸로, 없으면 사용자가 업로드 시 고르게. 매입이면 거래처=공급자, 매출이면 거래처=공급받는자. 행 스키마에 구분 값(예: `direction: 'sales'|'purchase'`)을 추가하되 기존 행(값 없음)은 매입으로 간주해 호환.
3. **행 생성**: 계산서 1건(승인번호 1개) = 목록 1행. 발행일=작성일자, 거래처, 사업자등록번호, 공급가액, 부가세=세액, 합계, 공종은 품목명으로 추정(기존 추정 로직이 있으면 재사용), 공사명은 빈칸(사용자 지정). 원본 파일은 엑셀 1개뿐이므로 각 행의 원본 참조 처리 방식을 정하라.
4. **중복 방지**: 같은 승인번호가 이미 목록에 있으면 건너뛰고, 업로드 결과로 "새로 추가 N건, 중복 건너뜀 M건"을 보여준다.
5. **공사명 일괄 지정**: 수십 건에 공사명을 하나씩 넣기 번거로우니, 체크한 행들에 공사명을 한 번에 넣는 방법(또는 거래처별 일괄 지정)을 간단히 설계.
6. **정산서 생성 연동**: 기존 "공사명으로 정산서 생성"에서 매입 행은 지금처럼 표1 외주·자재비 행으로, 매출 행은 정산서의 공급가액(projectInfo.supplyAmount, 합산)으로 반영. 기존 병합 규칙·결제금액 0 시작 규칙을 깨지 마라.
7. **사용법 안내**: 계산서함 안내 문구에 "홈택스에서 목록 엑셀 내려받는 경로"와 "올리면 여러 건이 한꺼번에 들어온다"는 설명 추가.
8. **테스트용 샘플**: Build 단계 브라우저 검증용으로, 위 헤더 구조를 흉내 낸 가짜 데이터 샘플 엑셀(매출·매입 각 1개, 실제 회사 정보 없음)을 만드는 방법을 계획에 포함. 샘플 파일은 저장소에 커밋하지 않는다.
