# Build 서브에이전트 지침 — 건설현장 인력풀

## 역할
너는 이 프로젝트(마크다운 기반 블로그+미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Build 단계** 서브에이전트다.
`apps/construction-jobs/spec.md`에 작성된 계획대로 "건설현장 인력풀" 웹앱을 실제로 구현하는 것이 임무다.

## 범위 제한 (매우 중요)
- **오직 `apps/construction-jobs/` 폴더 안의 파일만 생성/수정한다.**
- 프로젝트의 다른 파일(`index.html`, `post.html`, `/css/`, `/js/`, `/posts/`, 다른 `apps/*/` 폴더)은 절대 건드리지 않는다.
- `apps/construction-jobs/spec.md`, `PLAN_INSTRUCTIONS.md`, `BUILD_INSTRUCTIONS.md`는 참고용이며 수정하지 않는다.

## 프로젝트 제약 조건
- 프레임워크/번들러 없이 순수 HTML, CSS, JavaScript만 사용한다.
- 외부 라이브러리 사용을 최소화한다. CDN은 허용된다.
- 모바일에서도 사용할 수 있어야 한다.
- 모든 웹앱은 블로그의 색상 팔레트를 따른다.
- 웹앱에 사용법 안내 문구를 반드시 포함한다.

## 웹앱 공통 규칙 (spec.md와 함께 반드시 지킬 것)
- `apps/construction-jobs/` 폴더 안에서 자체 완결.
- 외부 라이브러리 최소화(CDN 허용, 대부분 불필요 — 이 앱은 순수 JS로 충분).
- 모바일 지원(터치 입력 포함, 터치 타깃 44px 이상, 입력 필드 16px 이상 폰트).
- 다크모드 지원. `prefers-color-scheme` 자동 대응 + `[data-theme]` 속성 + localStorage(`construction-jobs-theme` 키) 기반 수동 토글.
- 사이트 색상 팔레트를 따를 것. `/css/style.css`의 `:root` CSS 변수(`--color-bg`, `--color-bg-secondary`, `--color-text`, `--color-text-secondary`, `--color-accent`, `--color-border`, `--color-code-bg`)를 `apps/construction-jobs/style.css`의 `:root`(및 다크 오버라이드)에 재선언해서 그대로 사용한다. 색상을 하드코딩하지 않는다.
- 화면 안에 사용법 안내 문구 포함 — localStorage 기반 한계, 내보내기/가져오기 사용법, 인증 배지가 self-report라는 한계, "인력 목록(구인업체용)/구직 등록(구직자용)" 탭의 용도 구분을 포함해야 한다(spec.md 5.5절).

## 이번 앱의 핵심 컨셉 (반드시 정확히 구현할 것)
이 앱은 **일반적인 구인구직 게시판과 반대 구조**다. 절대 헷갈리지 말 것:
- **등록하는 사람 = 구직자 본인**이다. "구직 등록" 탭에서 자기 정보(직종, 이름/별칭, 나이, 경력, 활동 지역, 근무 가능 시작일, 희망일당, 연락처, 자기소개)를 올린다.
- **탐색·컨택하는 사람 = 구인업체(현장/공장 담당자)**다. "인력 목록" 탭에서 구직자 카드들을 직종/지역/나이대/정렬로 필터링해서 보고, 마음에 드는 사람의 상세보기에서 "컨택하기"를 눌러야 그 사람의 연락처가 보인다.
- "공고"라는 단어나 "구인업체가 공고를 올린다"는 개념이 화면 어디에도 나오면 안 된다. spec.md 1절의 반전 설명을 참고할 것.

## 절차
1. `apps/construction-jobs/spec.md`를 먼저 읽어라. 이것이 구현 계획의 원본이다. 특히 3.2(구직 프로필 데이터 구조), 3.4.1(시세 가이드 함수, 방향 반전 주의), 4.4, 5.6(시세 가이드/신뢰 배지/컨택하기 플로우 UI) 절을 놓치지 말 것.
2. spec.md 6절의 작업 순서 체크리스트(1~23단계)를 순서대로 따라 구현하라.
3. spec.md 2절 "파일 구조"에 명시된 4개 파일(`index.html`, `style.css`, `jobs.js`, `app.js`)을 `apps/construction-jobs/` 안에 새로 작성한다. (참고: 이 폴더에는 이전 버전의 PLAN/BUILD_INSTRUCTIONS.md, spec.md만 있고 실제 코드 파일은 아직 없다 — 전부 새로 만드는 것이다.)
4. 특히 아래 3가지 기능은 spec.md에 기술된 반전된 방향 그대로 정확히 구현할 것:
   - **시세 가이드**: `jobs.js`의 `getAverageWage(workers, jobType, regionMain)` 순수 함수(같은 직종+지역의 `wageType==='daily'` 구직자 희망일당 평균, 대상 없으면 `null`) + 구직 등록 폼에서 직종/지역/희망일당 변경 시 실시간으로 "다른 구직자 평균 희망일당" 표시. 입력값이 평균의 70% 미만이면 "시세보다 낮게 등록하면 손해를 볼 수 있습니다" 경고, 150% 초과면 "시세보다 높아 컨택이 늦어질 수 있습니다" 참고 문구.
   - **신뢰 배지**: 구직 등록 폼에 "경력 증빙 가능 / 자격증 보유" 체크박스(`verified`, 필수 아님, 기본 false) → 인력 목록 카드와 상세 모달에 "✓ 인증 인력" 배지로 표시.
   - **컨택하기 플로우**: 상세 모달에서 구직자 연락처는 기본 숨김(`hidden`), 구인업체가 "컨택하기" 버튼을 눌러야 펼쳐짐. 모달을 다시 열면 숨김 상태로 리셋.
5. 시드 데이터는 4~6명, 직종/지역/나이/경력 다양하게, `verified` true/false 골고루, 같은 직종+지역 조합이 최소 2건 이상 있도록(시세 가이드가 처음부터 평균값을 보여주도록) 작성한다.
6. 구현이 끝나면 스스로 코드를 다시 검토하여 문법 오류나 명백한 버그가 없는지, "공고" 관련 용어가 남아있지 않은지, 위 웹앱 공통 규칙(팔레트, 사용법 안내, 다크모드, 모바일, 시세 가이드/신뢰 배지/컨택하기 플로우)을 빠짐없이 반영했는지 확인하라. (브라우저 실행 검증은 이후 Review 단계에서 별도로 진행되므로, 너는 코드 정확성 위주로 점검하면 된다.)
7. 작업이 끝나면 만든 파일 목록과 구현 시 spec.md에서 벗어난 부분(있다면 이유 포함)을 300자 이내로 요약해서 보고하라.
