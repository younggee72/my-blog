# 건설현장 인력풀 구현 계획 (spec.md)

## 1. 개요

건설 현장에서 일할 사람을 찾는 **구인업체(현장/공장 담당자)**가 아니라, 반대로 **일이 필요한 구직자 본인이 자신의 구직 정보(직종, 나이, 경력, 근무 가능 시기, 희망 일당 등)를 직접 등록**하고, 구인업체가 그 인력 목록을 직종/지역/희망일당 등으로 필터링해 살펴본 뒤 마음에 드는 사람에게 컨택하는 **"인력풀(구직자 데이터베이스)" 웹앱**이다. 즉 등록 주체와 탐색 주체가 기존 구인구직 게시판과 반대다: 구직자가 자기 프로필을 올리고, 구인업체가 그 프로필을 검색·비교해서 먼저 연락한다.

**중요한 전제**: 이 프로젝트는 별도 백엔드/DB 없이 정적 파일만으로 동작하는 사이트이므로, 이 앱은 서버가 없는 순수 프런트엔드 웹앱이다. 구직자 프로필 데이터는 각 사용자의 브라우저 **localStorage**에만 저장되며, 다른 기기나 다른 브라우저와 자동으로 동기화되지 않는다. 즉, 실제로 구직자와 구인업체가 서로 다른 기기에서 실시간으로 매칭되는 다중 사용자 서비스가 아니라, **"한 브라우저 안에서 구직 프로필을 등록하고 열람·필터링해보는 로컬 저장 기반의 데모/열람 도구"**에 가깝다. 이 한계를 화면 안내 문구에도 명시한다. 데이터 공유 한계를 일부 완화하기 위해 등록된 구직 프로필 전체를 JSON 파일로 내보내기(export)하고, 그 파일을 다른 브라우저/기기에서 가져오기(import)할 수 있는 보조 기능을 둔다(예: 구직자가 프로필을 등록한 뒤 JSON을 내보내 카카오톡/메일 등으로 구인업체에 전달하면, 구인업체가 그 파일을 가져와 동일한 인력 목록을 볼 수 있음).

**제품 컨셉 시뮬레이션**: 사용자가 그리는 이 플랫폼의 지향점은 "배달앱에 등록하지 않으면 장사가 어려워지는 것"처럼, 구직자 입장에서는 이 인력풀에 자기 정보를 올려놓지 않으면 좋은 일자리 제안을 놓친다고 느끼고, 구인업체 입장에서는 자기 현장 수준에 맞는 적정 가격에 적정 숙련도의 인력을 찾는 데 지장이 없어야 한다는 것이다. 서버/DB/회원가입이 없는 정적 앱 특성상 실제 락인·매칭 알고리즘·후기 시스템까지는 구현할 수 없지만, 아래 3가지 기능으로 그 느낌을 **UX/데이터 설계 수준에서 시뮬레이션**한다.

1. **시세 가이드**: 구직 프로필 등록 시 같은 직종·지역의 다른 구직자들이 등록한 평균 희망 일당을 실시간으로 보여줘, 구직자가 자기 몸값을 시세에 맞게 책정하도록 돕는다.
2. **신뢰 배지**: self-report 방식의 "인증 인력" 배지로 경력/자격 증빙 여부를 시각적으로 구분한다(실제 검증이 아님을 명시).
3. **컨택하기 플로우**: 목록에서는 구직자 연락처를 감추고, 구인업체가 상세보기의 "컨택하기" 버튼을 눌러야 연락처가 펼쳐지게 해, "인력풀에 등록되어 있어야 컨택을 받을 수 있다"는 느낌을 준다.

이번 범위에서 후기/평점 시스템은 포함하지 않는다(향후 확장 아이디어로 5.6절 이후 별도 언급).

## 2. 파일 구조

```
/apps/construction-jobs/
  index.html    진입점. 헤더(제목+테마 토글), 사용법 안내, 탭 네비게이션(인력 목록 / 구직 등록), 목록 화면, 등록 폼, 상세보기 모달, 내보내기/가져오기 버튼 마크업과 css/js 로드
  style.css     레이아웃, 카드/폼/모달/뱃지 스타일, 다크모드, 반응형 스타일 (색상은 전부 사이트 CSS 변수 var() 참조)
  jobs.js       직종 목록 정의, 구직 프로필 데이터 구조(인증 여부 포함), localStorage 저장/조회, 필터/정렬 로직, 직종·지역별 평균 희망일당 계산(시세 가이드) 순수 함수, 시드 데이터
  app.js        DOM 렌더링, 폼 입력 처리/검증, 시세 가이드 실시간 표시, 인증 배지 렌더링, 탭 전환, 상세보기 모달(컨택하기 버튼/연락처 펼침 포함), 내보내기/가져오기, 다크모드 토글 이벤트 바인딩
```

- 앱 폴더 이름(`construction-jobs`)과 파일명(`jobs.js`, `app.js`)은 기존 구조를 그대로 유지한다(코드 재사용 및 리뷰 이력 연속성을 위해 변경하지 않음). 다만 `jobs.js` 안에서 다루는 데이터의 의미는 "공고"가 아니라 "구직 프로필"로 바뀐다.
- 이미지 리소스는 사용하지 않는다(아이콘은 이모지 또는 CSS로 대체).
- 외부 CDN 라이브러리는 사용하지 않는다(폼/목록/필터 수준의 기능은 순수 JS로 충분).
- `jobs.js`(데이터/로직)와 `app.js`(화면 렌더링/이벤트)를 분리해 Build 단계에서 각각 독립적으로 검증할 수 있게 한다.

## 3. 핵심 로직 설계

### 3.1 직종 목록 정의 방식

`jobs.js` 상단에 배열 상수로 정의하여 추가/수정이 쉽도록 한다(기존과 동일하게 유지).

```js
const JOB_TYPES = [
  { id: 'carpenter', label: '목수' },
  { id: 'rebar', label: '철근공' },
  { id: 'signal', label: '신호수' },
  { id: 'laborer', label: '잡부' },
  { id: 'formwork', label: '형틀목공' },
  { id: 'electrician', label: '전기공' },
  { id: 'plumber', label: '배관공' },
  { id: 'etc', label: '기타' },
];
```

- 필터 드롭다운, 구직 등록 폼의 직종 선택(select)이 모두 이 배열을 순회해 옵션을 생성하므로, 배열에 항목을 추가하면 UI 전체에 자동 반영된다.
- `id`는 저장 데이터의 `jobType` 필드 값으로 사용하고, `label`은 화면 표시용 한글명으로 분리해 향후 다국어 확장 여지를 남긴다.

### 3.2 구직 프로필 데이터 구조

기존 "공고(job posting)" 객체를 아래와 같이 **"구직 프로필(worker profile)"** 객체로 재설계한다.

```js
{
  id: string,            // crypto.randomUUID() 또는 타임스탬프+난수 조합
  jobType: string,       // JOB_TYPES의 id 중 하나 (희망 직종)
  name: string,          // 이름 또는 활동 별칭 (예: "김OO" 또는 "형틀 20년차 김반장")
  age: number,           // 나이 (만 나이, 정수)
  career: string,        // 경력/숙련도 요약 (자유 텍스트 또는 선택지: "신입/1~3년", "5년 이상", "10년 이상 숙련공" 등)
  regionMain: string,    // 활동 가능 광역 지역 (시/도 단위, select) - 기존 공고의 regionMain 필드를 그대로 재사용
  region: string,        // 활동 가능 상세 지역 (자유 입력, 선택)
  availableFrom: string, // 근무 가능 시작일 (YYYY-MM-DD)
  workDuration: string,  // 근무 가능 기간 구분: 'short'(단기, 며칠~몇 주) | 'long'(장기, 몇 개월 이상)
  desiredWage: number,   // 희망 일당(또는 희망 급여) 금액 (원 단위 정수)
  wageType: string,      // 'daily'(일당) | 'monthly'(월급) 등 희망 급여 단위 구분
  contact: string,       // 연락처 (전화번호 형식 텍스트)
  selfIntro: string,     // 자기소개/특이사항 (보유 자격증, 사용 가능 장비, 우대사항 등 자유 텍스트)
  createdAt: string,     // ISO 날짜 문자열, 등록 시각 (최신순 정렬용)
  verified: boolean,     // "경력 증빙 가능 / 자격증 보유" self-report 체크박스 값. true면 카드/상세보기에 "인증 인력" 배지 표시
}
```

- 필수 필드: `jobType`, `name`, `age`, `regionMain`, `availableFrom`, `desiredWage`, `contact`.
- 선택 필드: `career`, `region`(상세 지역), `workDuration`, `selfIntro`.
- `verified`는 폼의 체크박스에서 값을 받아 기본값 `false`로 저장한다(체크 안 하면 미인증 인력으로 취급). 실제 서류 검증이 아니라 구직자 본인이 스스로 체크하는 self-report라는 점을 5.5절 안내 문구에 명시한다.
- 시세 가이드(평균 희망일당 계산)는 별도 필드를 추가하지 않고 기존 `jobType`, `regionMain`, `desiredWage`, `wageType` 조합만으로 3.4.1절의 `getAverageWage` 함수가 계산한다.
- "공고 제목/모집 인원/작업 기간(startDate·endDate)/담당자명" 등 구인업체 관점의 필드는 모두 제거하고, 그 자리를 구직자 개인 정보(이름·나이·경력·근무가능시기)로 대체했다.

### 3.3 localStorage 저장/조회 방식

- Key: `construction-jobs-workers-list` — 구직 프로필 배열 전체를 JSON 문자열로 저장.
- 저장 함수 `saveWorkers(workersArray)`: `JSON.stringify` 후 `localStorage.setItem`.
- 조회 함수 `loadWorkers()`: `localStorage.getItem` → 값이 없으면 시드 데이터로 초기화 후 저장, 있으면 `JSON.parse`(파싱 실패 시 시드 데이터로 폴백하고 콘솔 경고).
- 등록/수정/삭제 시마다 전체 배열을 다시 저장하는 단순한 방식(구직자 수가 적어 성능 문제 없음).
- 최초 로드 시(저장된 데이터가 아예 없을 때)만 시드 데이터를 넣고, 이후 사용자가 전부 삭제해도 시드 데이터를 다시 채우지 않는다(별도 플래그 `construction-jobs-workers-initialized` 키로 최초 실행 여부 구분).
- `verified` 필드도 다른 필드와 동일하게 프로필 객체 안에 포함되어 저장/조회되므로 별도 storage key나 마이그레이션 로직이 필요 없다. 다만 가져오기(import)한 JSON에 `verified` 필드가 없는 구버전 데이터가 섞여 있을 수 있으므로, `loadWorkers`/가져오기 파싱 시 `verified`가 없으면 `false`로 기본 보정한다.

### 3.4 필터링/정렬 로직

- **직종 필터**: 드롭다운(또는 가로 스크롤 칩 버튼)에서 `JOB_TYPES` 중 하나 선택, "전체" 옵션 포함. 선택된 `jobType`과 일치하는 구직 프로필만 표시.
- **지역 필터**: `regionMain`(광역 단위) 드롭다운, "전체" 옵션 포함. 데이터에 등장하는 지역들을 동적으로 수집하거나 광역시/도 고정 목록을 사용.
- **나이대 필터(신규 제안)**: `age`를 20대/30대/40대/50대 이상 등 구간으로 묶어 선택할 수 있는 드롭다운. "전체" 옵션 포함, 구간 계산은 순수 함수 `getAgeGroup(age)`로 구현.
- **근무 가능 시기 필터(신규 제안)**: "즉시 가능"(오늘 이전 또는 당일 `availableFrom`) / "이번 달 내" / "전체"처럼 단순 구간으로 제공, 필수는 아니고 있으면 유용한 보조 필터로 제안.
- **정렬**: 셀렉트박스로 다음 옵션 제공
  - 최신 등록순(`createdAt` 내림차순, 기본값)
  - 희망일당 낮은순(`desiredWage` 오름차순, `wageType`이 다른 경우 월급은 일당 환산 없이 별도 배지로만 표시하고 정렬은 원 단위 숫자 그대로 비교하되 UI에 단위 혼재 안내 문구 추가)
  - 희망일당 높은순(`desiredWage` 내림차순)
  - 근무 가능일 임박순(`availableFrom` 오름차순)
- 필터+정렬은 순수 함수 `getFilteredWorkers(workers, { jobType, regionMain, ageGroup, sortKey })`로 구현해 배열을 복사·필터·정렬 후 반환(원본 배열 불변 유지).
- 검색창(이름/자기소개 텍스트 검색)은 선택적 추가 기능으로 UI 5장에서 제안.

### 3.4.1 시세 가이드 평균 희망일당 계산 (반전)

기존에는 "구인업체가 공고 등록 시 적정 일당을 가늠"하는 용도였다. 이제는 **구직자가 프로필을 등록할 때, 같은 직종·지역의 다른 구직자들이 등록한 평균 희망일당을 보여줘서 자기 몸값을 시세에 맞게 책정**하도록 돕는 용도로 방향이 바뀐다.

- `jobs.js`에 순수 함수 `getAverageWage(workers, jobType, regionMain)`를 유지한다(함수 시그니처는 동일, 대상 데이터만 구직 프로필 배열로 바뀜).
  - 입력받은 `workers` 배열에서 `jobType`과 `regionMain`이 모두 일치하는 프로필만 추리고, 그중 `wageType === 'daily'`(일당 희망)인 프로필만 대상으로 `desiredWage`의 산술 평균을 계산해 정수로 반환한다(월급 희망자는 단위가 달라 평균 계산 대상에서 제외).
  - 대상 프로필이 0건이면 `null`을 반환해, 호출부(app.js)가 "참고할 시세 데이터가 없습니다" 같은 안내로 대체 표시하게 한다.
  - 계산 대상은 시드 데이터 + 사용자가 등록한 프로필을 합친 현재 `loadWorkers()` 결과 전체이며, `verified` 여부와 무관하게 모두 포함한다(시세 왜곡을 피하기 위해 인증 인력만 별도로 거르지 않음).
  - 반환값은 등록 폼에서 실시간으로 참조되며(4.4절 참고), 아래 두 갈래 안내 문구 판단에 그대로 사용된다.
    - 입력한 희망 일당이 평균의 **70% 미만**이면: "시세보다 낮게 등록하면 손해를 볼 수 있습니다" 경고 문구.
    - 입력한 희망 일당이 평균의 **150% 초과**이면: "시세보다 높아 컨택이 늦어질 수 있습니다" 중립적 참고 문구.
    - 두 경우 모두 등록 자체를 막지는 않는 단순 안내다.

### 3.5 시드 데이터 설계 (구직자 프로필로 재작성)

- 처음 앱을 열었을 때 빈 화면이 되지 않도록 4~6명의 시드 구직 프로필을 `jobs.js`에 상수 배열로 포함한다.
- 직종을 목수/철근공/신호수/잡부 등 골고루 분포시키고, 지역도 서울/경기/인천 등 2~3곳으로 나누며, 나이는 20대~60대까지 다양하게, 희망 일당 값도 차등을 두어(예: 150,000원 ~ 220,000원) 정렬 기능을 시연할 수 있게 한다.
- `createdAt`도 서로 다른 과거 시각으로 설정해 최신순 정렬이 실제로 섞이도록 한다.
- `verified` 필드는 골고루 섞는다(예: 6명 중 3명은 `true`, 3명은 `false`). 같은 직종·지역 조합 안에서도 인증/미인증이 섞이도록 배치해, 목록 화면에서 인증 배지 유무에 따른 시각적 차이와 시세 가이드(3.4.1) 평균 계산이 인증 여부와 무관하게 동작하는 것을 함께 시연할 수 있게 한다.
- 같은 직종+`regionMain` 조합의 시드 프로필을 최소 2건 이상 포함시켜, 등록 폼에서 시세 가이드 평균값이 처음부터 의미 있게(0건이 아니게) 표시되도록 한다.
- `workDuration`(단기/장기)과 `career`(경력 수준)도 다양하게 섞어 필터/정렬 외의 정보 표시(카드 요약)가 단조롭지 않게 한다.

## 4. 입력 처리

### 4.1 구직 등록 폼 입력 검증

- `<form>` 제출(`submit` 이벤트)에서 `event.preventDefault()` 후 검증 진행.
- 필수 필드(직종, 이름/별칭, 나이, 광역지역, 근무 가능 시작일, 희망일당, 연락처)가 비어 있으면 해당 입력 아래 인라인 에러 메시지 표시하고 제출 중단, 첫 번째 오류 필드로 포커스 이동.
- HTML 기본 속성(`required`, `type="number"` + `min="0"`, `type="date"`, `type="tel"`)으로 1차 검증하고, JS에서 2차로 재검증(나이가 만 14~99 범위인지, 희망일당이 음수/0인지, 날짜 형식이 유효한지, 연락처가 숫자/하이픈 최소 자리수를 만족하는지 정규식으로 느슨하게 확인).
- 검증 통과 시 새 구직 프로필 객체 생성(`id`, `createdAt` 자동 부여, `verified`는 체크박스 상태 그대로 boolean으로 부여) → `saveWorkers`로 저장 → 목록 화면으로 전환하며 성공 토스트/안내 표시 → 폼 초기화(체크박스는 기본 미체크 상태로 리셋).
- "경력 증빙 가능 / 자격증 보유" 체크박스(`<input type="checkbox" name="verified">`)는 필수 필드가 아니며, 검증 로직에서 별도 에러 처리를 하지 않는다(체크 여부와 무관하게 제출 가능).

### 4.2 마우스/키보드/터치 처리

- 모든 인터랙션 요소(탭, 필터 드롭다운, 카드, 버튼, 모달 닫기)는 기본 `<button>`/`<select>`/`<a>` 등 시맨틱 요소를 사용해 클릭·키보드(Tab+Enter/Space)·터치를 기본적으로 모두 지원.
- 구직자 카드는 `<button>` 또는 `role="button"` + `tabindex="0"`으로 만들어 클릭/터치/Enter 키 모두로 상세보기 모달을 열 수 있게 한다.
- 상세보기 모달은 `Esc` 키로도 닫히도록 `keydown` 리스너 추가, 배경 클릭(오버레이 클릭)으로도 닫힘.
- 폼 입력 필드는 `inputmode="numeric"`(나이/희망일당), `inputmode="tel"`(연락처) 속성을 부여해 모바일 키보드가 숫자/전화 패드로 뜨도록 한다.

### 4.3 모바일 폼 사용성 고려

- 폼 필드는 세로 1열 배치(라벨 위, 입력 아래)로 통일해 좁은 화면에서도 잘리지 않게 한다.
- 입력 요소의 `font-size`를 최소 16px로 유지해 iOS 사파리에서 자동 확대(zoom)되는 현상을 방지한다.
- 버튼/입력 필드의 터치 타깃 높이를 최소 44px 이상 확보한다.
- select 요소는 네이티브 UI를 그대로 사용(커스텀 드롭다운 미구현)해 모바일 접근성/사용성을 확보한다.
- 구직자가 현장에서 스마트폰으로 직접 등록할 가능성이 높음을 고려해, 등록 폼 진입 버튼("구직 등록")을 목록 화면 어디서나 눈에 띄게 고정 배치(예: 하단 플로팅 버튼 또는 상단 탭)하는 것을 권장한다.

### 4.4 시세 가이드 실시간 표시 (반전)

- 구직 등록 폼의 직종(select), 광역지역(select), 희망일당(number input) 세 입력 중 하나라도 값이 바뀌면(`change`/`input` 이벤트) `getAverageWage(loadWorkers(), jobType, regionMain)`를 호출해 결과를 희망일당 입력 필드 아래 안내 영역에 실시간으로 갱신한다.
- 직종·지역이 아직 선택되지 않았거나 `wageType`이 `daily`가 아니면(월급 희망 선택 시) 시세 가이드 영역은 "일당 희망자 기준으로만 시세를 안내합니다" 등 안내로 대체하고 평균 계산을 생략한다.
- 평균값이 있으면 "이 직종/지역 다른 구직자 평균 희망일당: OOO원" 문구를 표시한다.
- 사용자가 입력한 `desiredWage` 값이 평균의 70% 미만이면 "시세보다 낮게 등록하면 손해를 볼 수 있습니다" 경고 문구를 같은 영역에 추가로 표시한다(입력 폼 제출을 막지는 않는 단순 안내).
- 평균 대비 현저히 높은 경우(평균의 150% 초과)는 제출을 막지 않고, "시세보다 높아 컨택이 늦어질 수 있습니다" 라는 중립적 참고 안내를 표시한다.
- 이 표시 로직은 `app.js`에서 담당하고, 평균 계산 자체(`getAverageWage`)는 3.4.1의 `jobs.js` 순수 함수를 그대로 호출해 재사용한다.

## 5. UI/디자인

### 5.1 레이아웃 구성

- 상단 헤더: 앱 제목("**건설현장 인력풀**") + 다크모드 토글 버튼(사이트 본체와 동일 패턴).
- 헤더 바로 아래: 짧은 사용법 안내 박스(상시 노출, 접기 가능) — "이 앱은 이 브라우저에만 저장되는 데모 도구입니다. 구직 등록 후 구인업체와 공유하려면 내보내기(JSON) 기능을 사용하세요." 등.
- 탭 네비게이션 2개: **[인력 목록]** / **[구직 등록]** — 탭 버튼 클릭으로 화면 전환(별도 페이지 이동 없이 같은 index.html 내에서 `display` 토글).
- **인력 목록 탭**(구인업체가 보는 화면): 상단에 필터바(직종 select, 지역 select, 나이대 select, 정렬 select) → 그 아래 구직자 카드 리스트(세로 스택, 각 카드는 직종 뱃지+이름(별칭)+나이+지역+경력 요약+희망일당+근무가능시기 요약 표시). `verified === true`인 프로필은 카드 우측 상단(또는 이름 옆)에 "인증 인력" 배지를 추가로 표시한다. 카드 단계에서는 연락처를 노출하지 않는다.
- 카드 클릭 시 **상세보기**는 모달(오버레이 + 중앙 패널)로 표시 — 경력, 자기소개, 근무 가능 기간 등 전체 필드를 노출하되 **연락처는 기본적으로 숨긴 상태**로 두고, "컨택하기" 버튼을 눌러야 연락처 영역이 펼쳐진다(5.6절 참고). `verified === true`면 모달 상단에도 "인증 인력" 배지를 표시한다. 닫기 버튼/배경클릭/Esc로 닫힘.
- **구직 등록 탭**(구직자가 자기 정보를 올리는 화면): 세로 폼(직종 select, 이름/별칭, 나이, 경력/숙련도, 광역지역 select, 상세지역 텍스트, 근무 가능 시작일, 근무 가능 기간(단기/장기), 희망일당/급여단위, 시세 가이드 실시간 안내 영역, 연락처, 자기소개/특이사항 textarea, "경력 증빙 가능 / 자격증 보유" 체크박스) + 등록 버튼.
- 목록 탭 하단 또는 헤더 우측에 **내보내기(Export JSON)** / **가져오기(Import JSON)** 버튼 배치 — 내보내기는 `Blob`+`<a download>`로 파일 다운로드, 가져오기는 `<input type="file">`로 JSON 파일 선택 후 파싱해 기존 목록에 병합(중복 `id`는 덮어쓰기) 또는 전체 교체 여부를 확인창으로 선택.

### 5.2 다크모드 대응

- 사이트 본체와 동일한 패턴을 그대로 따른다: `@media (prefers-color-scheme: dark)`로 `:root:not([data-theme='light'])`에 다크 팔레트 자동 적용 + `:root[data-theme='dark']`로 수동 오버라이드.
- 헤더 우측 원형 토글 버튼 클릭 시 `document.documentElement.setAttribute('data-theme', ...)` 값을 `light`/`dark` 사이에서 전환하고 `localStorage`(`construction-jobs-theme` 키)에 저장, 페이지 로드 시 저장된 값을 읽어 즉시 반영.

### 5.3 색상 팔레트 참조

- `apps/construction-jobs/style.css` 자체 `:root`에서 값을 하드코딩하지 않고, 사이트 본체가 쓰는 변수명을 그대로 재선언(다크모드 오버라이드 포함)해 이 앱이 단독으로 열려도(사이트 전역 CSS를 로드하지 않는 독립 폴더 구조이므로) 동일한 팔레트가 적용되도록 한다:
  - 배경: `var(--color-bg)`, `var(--color-bg-secondary)`
  - 텍스트: `var(--color-text)`, `var(--color-text-secondary)`
  - 강조색(버튼/뱃지/링크): `var(--color-accent)`
  - 테두리/구분선: `var(--color-border)`
  - 코드/인용 등 보조 배경: `var(--color-code-bg)` (필요 시 카드 배경 대체용으로 활용)
- 직종별 뱃지 색상은 별도 팔레트를 새로 만들지 않고 `--color-accent`를 기본으로, 배지 배경은 `--color-bg-secondary` + 텍스트는 `--color-text`로 통일해 팔레트 일관성을 유지한다(직종별 구분은 색상이 아닌 아이콘/텍스트 라벨로).

### 5.4 반응형 고려사항

- 브레이크포인트: `max-width: 640px`을 모바일 기준으로 사용(사이트 `--max-width: 700px`와 정합).
- 필터바는 데스크톱에서는 가로 flex 배치, 640px 이하에서는 세로 스택 또는 가로 스크롤 칩으로 전환.
- 구직자 카드 리스트는 항상 1열(세로 스택)로 통일해 모바일/데스크톱 모두 동일한 스캔 경험 제공(구인업체 담당자가 스마트폰으로 빠르게 훑어보는 사용성 우선).
- 모달은 데스크톱에서는 중앙 고정 폭 패널, 모바일에서는 화면 전체 폭에 가깝게(`width: 92vw` 또는 하단 시트 형태) 확대.
- 구직 등록 폼 입력 요소는 모바일에서 `width: 100%`로 확장.

### 5.5 사용법 안내 문구 배치

- 헤더 바로 아래에 상시 노출되는 안내 박스(연한 배경 + 아이콘)를 배치하고, 다음 내용을 포함한다:
  - 이 앱은 브라우저 localStorage에만 데이터가 저장되는 데모/도구이며, 다른 기기와 자동 동기화되지 않는다는 점.
  - **인력 목록 탭**(구인업체가 인력을 탐색하는 화면) / **구직 등록 탭**(구직자가 자기 정보를 올리는 화면) 전환 방법과 각 탭이 누구를 위한 화면인지 명확히 안내.
  - 필터/정렬 사용법(직종·지역·나이대 선택, 정렬 기준 변경).
  - 구인업체와 공유하려면 내보내기(JSON)로 파일을 저장해 전달하고, 받는 쪽은 가져오기로 불러오면 된다는 안내.
- 안내 박스는 접기/펼치기 토글(작은 "닫기"/"다시 보기" 버튼)을 지원해, 한번 확인한 사용자가 화면을 더 넓게 쓸 수 있게 한다(닫힘 상태도 선택적으로 localStorage에 기억).
- 안내 문구에 "인증 인력 배지는 경력 증빙/자격증 보유를 등록자가 스스로 체크한 self-report이며, 실제 서류 검증을 거친 것이 아니다"라는 한계도 명시한다.

### 5.6 시세 가이드 · 신뢰 배지 · 컨택하기 플로우 UI (반전)

- **시세 가이드**: 구직 등록 폼의 희망일당(desiredWage) 입력 필드 바로 아래에 작은 안내 텍스트 영역(`<p id="wage-guide">` 등)을 두고, 4.4절 로직이 갱신하는 "다른 구직자 평균 희망일당: OOO원" 문구와 필요 시 경고/참고 문구(시세 대비 낮음/높음)를 이 영역에 표시한다. 평균보다 낮을 때는 경고 색상(예: 사이트 팔레트에 있는 경고색이 없다면 `--color-accent`를 활용하되 텍스트에 "낮음"을 명시해 색에만 의존하지 않음)으로 강조한다.
- **신뢰 배지**: 카드 컴포넌트와 상세보기 모달 양쪽에서 동일한 배지 마크업(예: `<span class="badge badge-verified">✓ 인증 인력</span>`)을 재사용한다. 배지 배경/텍스트 색은 5.3절의 팔레트 규칙(`--color-accent` 계열)을 따르되, 일반 직종 뱃지와 시각적으로 구분되도록 아이콘(✓ 등)을 추가한다.
- **컨택하기 플로우**: 상세보기 모달 내부에 연락처 영역을 `<div id="contact-area" hidden>`처럼 기본 숨김으로 두고, 그 위에 "컨택하기" 버튼을 배치한다. **구인업체 담당자**가 이 버튼을 클릭하면 `hidden` 속성을 제거(또는 `display` 토글)해 구직자의 전화번호가 화면에 펼쳐진다. 서버 인증이 없으므로 순수 클라이언트 인터랙션이며, 펼쳐진 뒤에는 버튼 텍스트를 "연락처 확인됨" 등으로 바꾸거나 비활성화해 다시 누를 필요가 없음을 알린다. 이 인터랙션은 모달을 다시 열면 초기 숨김 상태로 리셋된다(별도로 컨택 여부를 저장하지 않음). 클릭 주체만 구직자→구인업체로 바뀔 뿐, hidden→버튼 클릭 시 펼침→모달 재오픈 시 리셋이라는 메커니즘 자체는 기존과 동일하게 재사용한다.
- **향후 확장 아이디어**(이번 범위 밖, 참고용 메모): 구인업체가 컨택 후 남기는 후기/평점 시스템, 실제 자격증/경력증명서 검증 연동, 컨택 이력 저장 등은 서버/회원 시스템이 필요해 이번 정적 앱 범위에서는 제외한다.

## 6. 작업 순서 (Build 단계 체크리스트)

1. `apps/construction-jobs/index.html` 뼈대 작성: 헤더(제목 "건설현장 인력풀"+다크모드 토글), 사용법 안내 박스(신뢰 배지 한계 문구 포함), 탭 네비게이션(인력 목록/구직 등록), 목록 화면 컨테이너(필터바+카드리스트 자리), 구직 등록 폼 마크업(시세 가이드 표시 영역 자리, 인증 확인 체크박스 자리 포함), 상세보기 모달 마크업(인증 배지 자리, 컨택하기 버튼 + 숨김 연락처 영역 자리 포함), 내보내기/가져오기 버튼, css/js 링크.
2. `apps/construction-jobs/style.css`에 사이트 CSS 변수 재선언(라이트/다크) 및 기본 레이아웃(헤더, 안내박스, 탭) 스타일 작성. 인증 배지, 시세 가이드 경고 문구 스타일도 함께 정의.
3. `jobs.js`에 `JOB_TYPES` 배열, 구직 프로필 데이터 구조(3.2절, `verified` 필드 포함)에 맞춘 시드 데이터(4~6명, `verified` true/false 골고루 분포) 작성.
4. `jobs.js`에 `loadWorkers`/`saveWorkers`(localStorage 연동, 최초 실행 시 시드 주입, `verified` 누락 시 `false` 보정) 함수 구현 및 콘솔에서 동작 확인.
5. `jobs.js`에 `getFilteredWorkers(workers, options)` 필터/정렬 순수 함수 구현(직종/지역/나이대/정렬 4종) 및 임시 콘솔 테스트.
6. `jobs.js`에 `getAverageWage(workers, jobType, regionMain)` 시세 평균 계산 순수 함수 구현(3.4.1절, 대상은 `desiredWage`) 및 임시 콘솔 테스트(대상 0건일 때 `null` 반환 확인 포함).
7. `app.js`에 구직자 카드 렌더링 함수 구현: `loadWorkers()` 결과를 목록 화면에 카드로 그리기(직종 뱃지, 이름, 나이, 지역, 경력 요약, 희망일당, `verified`면 인증 배지 추가).
8. 필터바(직종 select, 지역 select, 나이대 select, 정렬 select) DOM 생성 및 변경 이벤트 → `getFilteredWorkers` 호출 → 카드 리스트 재렌더링 연결.
9. 탭 전환(인력 목록/구직 등록) 로직 구현: 버튼 클릭 시 활성 탭 표시 전환 및 각 화면 `display` 토글.
10. 구직 등록 폼 필드별 마크업 완성(select/input/textarea, "경력 증빙 가능 / 자격증 보유" 체크박스 포함) 및 CSS 스타일링(세로 배치, 모바일 폭 100%).
11. 등록 폼의 직종/지역/희망일당 입력에 `change`·`input` 이벤트 바인딩 → `getAverageWage` 호출 → 시세 가이드 문구("평균 희망일당: OOO원") 및 70% 미만 경고/150% 초과 참고 문구 실시간 표시 구현(4.4절).
12. 구직 등록 폼 제출 검증 로직 구현(필수값, 나이·희망일당 범위, 날짜 형식, 연락처 형식) 및 인라인 에러 메시지 표시(`verified` 체크박스는 필수 아님).
13. 검증 통과 시 새 구직 프로필 저장(`id`/`createdAt`/`verified` 부여) → `saveWorkers` → 인력 목록 탭으로 전환 + 카드리스트 재렌더링 + 성공 안내 토스트 구현.
14. 카드 클릭/키보드(Enter)/터치 시 상세보기 모달 오픈 로직 구현: 전체 필드 표시(연락처 영역은 기본 숨김), `verified`면 모달에도 인증 배지 표시.
15. 상세보기 모달의 "컨택하기" 버튼 클릭 시 숨겨진 연락처 영역을 펼치는 로직 구현(5.6절), 모달을 다시 열면 숨김 상태로 리셋되는지 확인.
16. 모달 닫기(닫기버튼/배경클릭/Esc) 및 접근성(포커스 이동) 처리.
17. 내보내기 기능 구현: 전체 구직 프로필 배열(`verified` 포함)을 JSON으로 `Blob` 생성 후 `<a download>`로 파일 다운로드.
18. 가져오기 기능 구현: `<input type="file">`로 JSON 선택 → 파싱(형식 오류 시 에러 안내, `verified` 누락 필드는 `false`로 보정) → 병합/교체 여부 확인창 → `saveWorkers` → 목록 재렌더링.
19. 다크모드 수동 토글 버튼 구현 및 localStorage(`construction-jobs-theme`) 연동, 페이지 로드 시 즉시 반영.
20. 사용법 안내 박스 접기/펼치기 토글 구현.
21. 반응형 스타일 점검: 320~420px 좁은 화면에서 필터바/카드/폼/모달/시세 가이드 영역 레이아웃 확인 및 조정, 터치 타깃 44px 이상 확보 확인.
22. 라이트/다크 모드 각각에서 전체 화면(인력 목록/구직 등록/상세모달/안내박스/인증 배지/시세 가이드 경고문구) 육안 점검.
23. 엣지 케이스 점검: 등록된 구직자 0명일 때 목록 화면 안내 문구, 필터 결과 0건일 때 안내 문구, 시세 가이드 대상 0건일 때 안내 문구, localStorage 파싱 실패 시 폴백, 가져오기 파일이 잘못된 형식일 때 에러 처리, 컨택하기 버튼 반복 클릭 시 동작, 새로고침 후 데이터/테마 유지 여부.
