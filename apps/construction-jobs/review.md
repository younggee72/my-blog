# Review 결과 — 건설현장 인력풀 (반전 버전: 구직자 등록 → 구인업체 컨택)

> 이 문서는 최신 코드(구직자가 등록하고 구인업체가 컨택하는 반전 구조)를 기준으로 처음부터 재검증한 결과다.
> 폴더에 남아있던 이전 `review.md`(반대 방향 버전 검증)는 낡은 문서이므로 이 내용으로 전체 교체했다.

## 검증 범위
- 대상 파일: `apps/construction-jobs/index.html`, `style.css`, `jobs.js`, `app.js`
- 참고 문서: `apps/construction-jobs/spec.md`
- 방법: 코드 정독 + spec.md 대조, `python -m http.server`(`.claude/launch.json`의 `static-server` 설정)로 정적 서버를 띄운 뒤 브라우저 프리뷰 도구로 실제 조작

## 1. 컨셉/용어 일치 여부 — 통과
- `index.html`/`app.js`/`jobs.js` 전체에서 "공고" 관련 잔재 용어 없음. "구직 프로필", "인력 목록", "구직 등록", "컨택하기" 등 반전 컨셉에 맞는 용어만 사용됨.
- 등록 주체(구직자)와 탐색 주체(구인업체)가 spec.md 1절 설명과 정확히 일치.

## 2. spec.md 대조 — 통과
- 3.2 데이터 구조: `id/jobType/name/age/career/regionMain/region/availableFrom/workDuration/desiredWage/wageType/contact/selfIntro/createdAt/verified` 필드 모두 구현됨.
- 3.4.1 시세 가이드: `getAverageWage(workers, jobType, regionMain)`가 `wageType === 'daily'`만 대상으로 평균 계산, 0건이면 `null` 반환, 70% 미만/150% 초과 문구 분기 모두 구현·동작 확인.
- 4.4 실시간 표시: 직종/지역/희망일당 입력 변경 시 `wage-guide` 영역이 실시간 갱신됨(브라우저에서 직접 확인).
- 5.6 컨택하기 플로우: 상세 모달에서 연락처 기본 숨김 → "컨택하기" 클릭 시 펼침 + 버튼이 "연락처 확인됨"으로 비활성화 → 모달을 닫고 다시 열면 숨김 상태로 리셋됨을 실제 클릭으로 확인.

## 3. 웹앱 공통 규칙 — 통과
- 색상 팔레트: `style.css`의 `--color-bg/--color-bg-secondary/--color-text/--color-text-secondary/--color-accent/--color-border/--color-code-bg` 값이 `/css/style.css`(사이트 본체)와 라이트/다크 모두 동일한 값으로 재선언되어 있음(하드코딩된 임의 색상 없음).
- 사용법 안내: 헤더 아래 안내 박스에 localStorage 한계, 내보내기/가져오기 안내, 인력 목록/구직 등록 탭 각각의 대상(구인업체/구직자), 인증 배지가 self-report라는 한계까지 모두 포함되어 있고 접기/펼치기 토글도 정상 동작.
- 다크모드: 자동(`prefers-color-scheme`) + 수동 토글 버튼 모두 실제 클릭으로 정상 동작 확인(아이콘 전환, 배경/텍스트/버튼 색 전환 모두 정상).
- 모바일 대응: 375px, 320px에서 실제 리사이즈 후 확인 — 카드 리스트, 등록 폼, 상세 모달 모두 잘림/겹침 없이 정상 표시.

## 4. 브라우저 실동작 검증 — 통과 (아래 항목 모두 직접 조작하여 확인)
- 인력 목록 탭: 시드 구직자 6명 카드 정상 노출, 직종 필터(목수만 필터링됨), 지역 필터(제주 선택 시 "조건에 맞는 구직자가 없습니다" 안내 정상 노출), 나이대 필터, 정렬(최신순/희망일당 낮은순/높은순/근무가능일 임박순) 옵션 정상 동작.
- 카드 클릭 → 상세 모달 오픈, 연락처 기본 숨김, 컨택하기 클릭 시 연락처 노출 및 버튼 비활성화, Esc/배경클릭으로 닫힘, 재오픈 시 리셋 확인.
- 구직 등록 탭: 직종=목수·지역=서울 선택 시 시세 가이드 "평균 희망일당: 205,000원" 정상 표시. 희망금액 100,000원 입력 시 "낮음: 시세보다 낮게 등록하면 손해를 볼 수 있습니다" 경고, 400,000원 입력 시 "참고: 시세보다 높아 컨택이 늦어질 수 있습니다" 안내 정상 노출.
- 필수값 검증: 이름/나이/근무가능시작일/연락처를 비운 채 제출 시 각 필드 아래 인라인 에러 메시지 정상 노출, "경력 증빙 가능/자격증 보유" 체크박스는 필수 아님 확인.
- 정상 제출: 신규 구직 프로필이 목록 최상단(최신순)에 인증 배지와 함께 정상 반영됨.
- 엣지 케이스: localStorage를 빈 배열로 만들면 "등록된 구직자가 없습니다..." 안내 노출, 시세 가이드 대상 0건이면 "아직 참고할 시세 데이터가 없습니다" 노출, localStorage 값이 손상된 JSON이면 콘솔 경고 후 시드 데이터로 정상 폴백. 가져오기(import) 시 `verified` 필드 누락 데이터가 `false`로 보정되는 로직도 코드 실행으로 확인.
- 콘솔 에러: 없음(의도된 파싱 실패 테스트 시의 `console.warn`만 발생, 이는 정상 동작).

## 5. 발견 및 수정한 문제

### [수정 완료] 모바일(640px 이하)에서 필터바 항목 사이 불필요한 빈 공간
- **증상**: `style.css`의 `.filter-field { flex: 1 1 140px; }`는 원래 데스크톱 가로 배치에서 각 필터의 최소 너비(140px)를 지정하려는 의도였다. 그런데 640px 이하 미디어쿼리에서 `.filter-bar`가 `flex-direction: column`으로 바뀌면서, flex의 주축이 세로로 바뀌어 `flex-basis: 140px`가 **너비가 아니라 높이**에 적용됐다. 그 결과 라벨+select 실제 높이(약 65px)보다 훨씬 큰 140px 높이가 각 필터 필드에 강제되어, 375px/320px 화면에서 필터바가 불필요하게 늘어지는 문제가 있었다.
- **수정**: `apps/construction-jobs/style.css`의 `@media (max-width: 640px)` 블록에 `.filter-field { flex-basis: auto; }`를 추가해, 모바일에서는 flex-basis가 내용물 크기를 따르도록 했다.
- **재검증**: 375px/320px 리사이즈 후 스크린샷으로 필터 4개(직종/지역/나이대/정렬)가 빈 공간 없이 촘촘하게 붙어 표시됨을 확인.

그 외 코드 전반(폼 검증, 모달, 내보내기/가져오기, 다크모드, 시세 가이드)에서 추가로 발견된 버그는 없음.

## 최종 결론
**정상 배포 가능.** spec.md의 요구사항(반전된 구조: 구직자 등록 → 구인업체 필터링/컨택, 시세 가이드, 신뢰 배지, 컨택하기 플로우)이 코드에 정확히 반영되어 있고, "공고" 관련 잔재 용어도 없다. 발견된 모바일 레이아웃 버그 1건은 `apps/construction-jobs/style.css` 안에서 수정 완료했다. 사이트 공통 규칙(팔레트, 사용법 안내, 다크모드, 반응형)도 모두 충족한다.
