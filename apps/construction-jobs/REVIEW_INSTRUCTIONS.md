# Review 서브에이전트 지침 — 건설현장 인력풀

## 역할
너는 이 프로젝트(마크다운 기반 블로그+미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Review 단계** 서브에이전트다.
Build 단계에서 새로 구현된 "건설현장 인력풀"(`apps/construction-jobs/` 안의 파일들)을 검증하는 것이 임무다.
너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

**중요**: `apps/construction-jobs/review.md`와 `REVIEW_INSTRUCTIONS.md`(구버전)가 이미 폴더에 남아있을 수 있는데, 그것은 예전의 **반대 방향(구인업체가 공고 등록)** 버전을 검증했던 낡은 결과물이다. 지금 폴더의 `index.html`/`style.css`/`jobs.js`/`app.js`는 그 이후 **완전히 새로 구현된, 반전된(구직자가 등록 → 구인업체가 컨택) 버전**이다. 이번 리뷰는 이 최신 코드를 기준으로 처음부터 다시 검증하고, `apps/construction-jobs/review.md`를 최신 내용으로 덮어써라.

## 범위 제한
- 검증 대상은 `apps/construction-jobs/` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/construction-jobs/` 폴더 안의 파일만 수정**한다. 프로젝트의 다른 파일(`index.html`(블로그 루트), `post.html`, `/css/`, `/js/`, `/posts/`, 다른 `apps/*/` 폴더)은 건드리지 않는다.
- 최종 산출물로 `apps/construction-jobs/review.md`를 (덮어써서) 작성한다.

## 참고 문서
- `apps/construction-jobs/spec.md` — 원래 계획 (이 계획대로 구현됐는지 대조, 특히 3.2/3.4.1/4.4/5.6절)
- `apps/construction-jobs/` 안의 코드 파일(`index.html`, `style.css`, `jobs.js`, `app.js`) — 검증 대상

## 핵심 컨셉 (검증 시 절대 헷갈리지 말 것)
이 앱은 일반적인 구인구직 게시판과 반대다:
- **등록하는 사람 = 구직자 본인** ("구직 등록" 탭에서 자기 직종/이름/나이/경력/희망일당/연락처 등록)
- **탐색·컨택하는 사람 = 구인업체** ("인력 목록" 탭에서 구직자 카드를 필터링해서 보고, 상세보기의 "컨택하기" 버튼을 눌러야 그 구직자의 연락처가 보임)
- 화면 어디에도 "공고"라는 단어나 "구인업체가 공고를 올린다"는 개념이 남아있으면 안 된다.

## 검증 절차
1. spec.md를 읽고 요구사항 목록을 파악한다.
2. 코드를 읽고 spec.md와 대조하여 누락되거나 다르게 구현된 부분, 그리고 "공고" 관련 잔재 용어가 있는지 확인한다.
3. 웹앱 공통 규칙이 실제로 지켜졌는지 확인한다:
   - 사이트 색상 팔레트(`/css/style.css`의 `--color-bg`, `--color-text`, `--color-accent` 등 CSS 변수)를 실제로 참조하고 있는지, 앱만의 임의 색상을 하드코딩하지 않았는지
   - 화면 안에 사용법 안내 문구가 실제로 보이는지 (localStorage 한계, 내보내기/가져오기, 인증 배지가 self-report라는 한계, "인력 목록/구직 등록" 각 탭이 누구를 위한 화면인지 안내 포함)
   - 다크모드가 실제로 동작하는지 (자동 + 수동 토글)
   - 모바일 크기(예: 375px, 320px)에서 레이아웃이 깨지지 않는지
4. 브라우저 프리뷰 도구(preview_start 등)로 `apps/construction-jobs/index.html`을 정적 서버로 띄워 실제 동작을 확인한다. 다음 핵심 기능을 실제로 조작해보며 검증한다:
   - **인력 목록 탭**에서 시드 구직자 카드가 보이는지, 직종/지역/나이대 필터와 정렬(최신순/희망일당높은순/낮은순/근무가능일임박순)이 실제로 동작하는지
   - 카드 클릭 시 상세 모달이 열리는지, 연락처가 기본 숨김 상태인지, **"컨택하기"** 버튼을 눌러야 연락처가 펼쳐지는지, 모달을 닫았다 다시 열면 숨김 상태로 리셋되는지
   - **구직 등록 탭**에서 직종/지역/희망일당을 입력했을 때 시세 가이드(다른 구직자 평균 희망일당) 문구가 실시간으로 뜨는지, 평균의 70% 미만으로 입력하면 "손해를 볼 수 있습니다" 류 경고가, 150% 초과 입력 시 "컨택이 늦어질 수 있습니다" 류 참고 문구가 뜨는지
   - "경력 증빙 가능 / 자격증 보유" 체크박스를 체크하고 등록하면 카드/상세보기에 "인증 인력" 배지가 뜨는지
   - 구직 등록 폼 필수값 검증(빈 값 제출 시 에러)
   - 내보내기(JSON 다운로드) 및 가져오기(JSON 업로드) 동작
   - 다크모드 토글 버튼 동작
   - 브라우저 콘솔에 에러가 없는지
5. 코드 자체도 훑어보며 명백한 버그, 예외 상황 미처리(등록된 구직자 0명/필터 결과 0건/시세 가이드 대상 0건일 때 안내), 다크모드 미대응 요소, "공고" 잔재 용어가 없는지 점검한다.
6. **문제를 발견하면 그 자리에서 `apps/construction-jobs/` 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 3~5번부터 재검증한다.
7. 모든 검증이 끝나면 `apps/construction-jobs/review.md`를 (기존 내용을 덮어써서) 새로 작성한다. 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면, 무엇을 어떻게 고쳤는지)
   - 최종 결론: 정상 배포 가능한지 여부
8. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
