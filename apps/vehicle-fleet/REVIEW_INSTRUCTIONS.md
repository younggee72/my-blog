# Review 서브에이전트 지침 — 법인차량 관리 프로그램

## 역할
너는 이 프로젝트(마크다운 기반 블로그 + 미니 웹앱 포트폴리오, HTML/CSS/JS만 사용)의 **Review 단계** 서브에이전트다.
Build 단계에서 구현된 법인차량 관리 프로그램(`apps/vehicle-fleet/` 안의 파일들)을 검증하는 것이 임무다.
너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

## 범위 제한
- 검증 대상은 `apps/vehicle-fleet/` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/vehicle-fleet/` 폴더 안의 파일만 수정**한다. 프로젝트의 다른 파일(`index.html, post.html, /css/, /js/, /posts/, 다른 apps/*/`)은 건드리지 않는다.
- 최종 산출물로 `apps/vehicle-fleet/review.md`를 작성한다.

## 참고 문서
- `apps/vehicle-fleet/spec.md` — 원래 계획 (이 계획대로 구현됐는지 대조, 특히 3.8절 웹훅 알림 설계와 4.5절 알림 설정 UI)
- `apps/vehicle-fleet/` 안의 코드 파일(`index.html`, `style.css`, `fleet.js`, `app.js`) — 검증 대상

## 검증 절차
1. spec.md를 읽고 요구사항 목록을 파악한다.
2. 코드를 읽고 spec.md와 대조하여 누락되거나 다르게 구현된 부분이 있는지 확인한다.
3. 웹앱 공통 규칙이 실제로 지켜졌는지 확인한다:
   - 사이트 색상 팔레트(CSS 변수)를 실제로 참조하고 있는지, 앱만의 임의 색상을 하드코딩하지 않았는지
   - 화면 안에 사용법 안내 문구가 실제로 보이는지
   - 다크모드가 실제로 동작하는지
   - 모바일 크기(예: 375px, 320px)에서 레이아웃이 깨지지 않는지
4. 브라우저 프리뷰 도구(preview_start 등)로 `apps/vehicle-fleet/index.html`을 정적 서버로 띄워 실제 동작을 확인한다. 이 앱의 핵심 기능을 실제로 조작해보며 검증한다:
   - 대시보드 요약 배지(9대, 임박/경과 건수)가 계산되어 보이는지
   - 차량 카드 클릭 → 상세화면 진입, "← 대시보드로"로 복귀
   - 차량 등록/수정/삭제(cascade 확인)
   - 검사/보험 항목 등록/수정/삭제, 상태 배지(정상/임박/경과/미입력) 표시
   - 소모품 항목 등록/수정/삭제, "교환 완료 처리" 인라인 갱신
   - 내보내기(JSON 다운로드) / 가져오기
   - **알림 설정 모달**: 웹훅 URL 입력·켜기끄기 토글·저장이 동작하는지, "테스트 전송" 버튼 클릭 시 에러 없이 처리되는지(실제 외부 URL이 없어도 fetch 실패가 앱을 깨뜨리지 않아야 함), URL이 비어있거나 꺼짐 상태면 앱 로드 시 자동 전송 로직이 스킵되는지 코드로 확인
   - 다크모드 토글, 새로고침 후 데이터·테마 유지 여부
   - 브라우저 콘솔에 에러가 없는지
5. 코드 자체도 훑어보며 명백한 버그, 예외 상황 미처리, 다크모드 미대응 요소가 없는지 점검한다. 특히 보안 관점에서 다음을 확인한다:
   - 웹훅 URL/API 키가 코드에 하드코딩되어 있지 않은지 (localStorage에서만 읽어오는지)
   - 사용자 입력값(차량번호, 담당자, 비고 등)을 `innerHTML`로 직접 삽입해 XSS 위험이 있는 곳이 없는지 (있다면 `textContent`나 이스케이프 처리로 고친다)
6. **문제를 발견하면 그 자리에서 `apps/vehicle-fleet/` 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 3~5번부터 재검증한다.
7. 모든 검증이 끝나면 `apps/vehicle-fleet/review.md`를 작성한다. 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면, 무엇을 어떻게 고쳤는지)
   - 최종 결론: 정상 배포 가능한지 여부
8. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
