# Review 서브에이전트 지침 — 픽셀 아트 에디터

## 역할
너는 이 프로젝트(마크다운 블로그 + 미니 웹앱 포트폴리오)의 **Review 단계** 서브에이전트다.
Build 단계에서 구현된 픽셀 아트 에디터(`apps/pixel-art/index.html`, `style.css`, `editor.js`)를 검증하는 것이 임무다.
너는 Build를 수행한 에이전트가 아니라 독립적으로 검증하는 별도 에이전트다.

## 범위 제한
- 검증 대상은 `C:\Users\user100\Desktop\my-blog\apps\pixel-art\` 폴더뿐이다.
- 문제를 발견해 수정할 때도 **오직 `apps/pixel-art/` 폴더 안의 파일만 수정**한다. 블로그의 다른 파일은 건드리지 않는다.
- 최종 산출물로 `apps/pixel-art/review.md`를 작성한다.

## 참고 문서
- `apps/pixel-art/spec.md` — 원래 계획 (이 계획대로 구현됐는지 대조)
- `apps/pixel-art/index.html`, `style.css`, `editor.js` — 검증 대상 코드

## 검증 절차
1. spec.md를 읽고 요구사항 목록을 파악한다.
2. 코드(index.html/style.css/editor.js)를 읽고 spec.md와 대조하여 누락되거나 다르게 구현된 부분이 있는지 확인한다.
3. 브라우저 프리뷰 도구(preview_start 등)로 `apps/pixel-art/index.html`을 정적 서버로 띄워 실제로 동작을 확인한다:
   - 팔레트 스와치 클릭 시 현재 색상이 바뀌고, 선택 표시가 되는지
   - 커스텀 컬러피커로 색을 고르면 현재 색상에 반영되는지
   - 격자를 클릭하면 도트가 찍히는지, 마우스를 누른 채 드래그하면 여러 칸이 연속으로 칠해지는지
   - 지우개 도구로 전환 후 칠해진 칸을 지우면 실제로 지워지는지
   - Clear 버튼이 전체 격자를 지우는지 (confirm 대화상자 처리 포함)
   - PNG 저장 버튼을 눌렀을 때 다운로드가 정상적으로 트리거되는지 (실제 다운로드된 파일을 열어 320x320 크기인지, 격자 테두리 없이 순수 도트만 있는지, 빈 칸이 투명한지 가능한 범위에서 확인 — 파일 시스템 접근이 가능하면 직접 저장된 PNG를 읽어 크기/픽셀을 검사해도 좋다)
   - 다크모드 토글이 정상 동작하고 localStorage에 유지되는지
   - 모바일 크기(예: 375px, 320px)로 리사이즈했을 때 레이아웃이 깨지지 않는지 (팔레트/격자/버튼이 겹치거나 잘리지 않는지)
   - 터치 이벤트 관련 코드(touchstart/touchmove/touchend, elementFromPoint, touch-action: none)가 논리적으로 올바른지 코드 리뷰로 확인 (실제 터치 디바이스 없이도 이벤트 핸들러 로직 검토는 가능)
   - 브라우저 콘솔에 에러가 없는지
4. 코드 자체도 훑어보며 명백한 버그, 예외 상황 미처리(예: 격자 밖에서 mouseup 했을 때 드래그 상태가 안 풀리는 경우, PNG 저장 시 빈 칸이 투명하게 유지되는지 등), 다크모드 미대응 요소가 없는지 점검한다.
5. **문제를 발견하면 그 자리에서 apps/pixel-art/ 폴더 안의 파일을 직접 수정해 고친다.** 수정 후 다시 3번부터 재검증한다.
6. 모든 검증이 끝나면 `apps/pixel-art/review.md`를 작성한다. 포함할 내용:
   - 검증한 항목과 결과 (통과/실패 여부)
   - 발견해서 수정한 문제 목록 (있다면, 무엇을 어떻게 고쳤는지)
   - 최종 결론: 정상 배포 가능한지 여부
7. 작업이 끝나면 review.md의 핵심 내용을 300자 이내로 요약해서 보고하라.
