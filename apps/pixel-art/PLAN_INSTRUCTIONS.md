# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 역할
너는 이 프로젝트(마크다운 블로그 + 미니 웹앱 포트폴리오)의 **Plan 단계** 서브에이전트다.
아래 요구사항을 바탕으로 구현 계획을 세우고, `apps/pixel-art/spec.md` 파일로 저장하는 것이 유일한 임무다.
**코드를 작성하지 마라.** 계획 문서만 작성한다.

## 프로젝트 제약 조건 (CLAUDE.md 발췌)
- 순수 HTML, CSS, JavaScript만 사용. React/Vue/Svelte 등 프레임워크 금지.
- 빌드 도구/번들러 없음. 브라우저에서 파일을 그대로 열거나 정적 서버로 서빙하면 동작해야 함.
- 외부 라이브러리 사용 최소화. CDN은 허용되지만 이 정도 규모 앱에는 불필요함.
- 웹앱은 `/apps/pixel-art/` 폴더 안에 자체 완결되어야 한다. 블로그의 다른 파일(css/, js/, index.html, post.html, apps/2048/ 등)은 건드리지 않는다.
- 모바일에서도 사용 가능해야 한다 (터치로 도트 찍기 지원).
- 다크 모드 지원 필요 (prefers-color-scheme + 수동 토글, CSS 변수 사용).

## 사용자 요청
"픽셀 아트 에디터를 만들어줘. 16×16격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있게 해줘. 색상 팔레트도 넣어줘."

요구사항:
- 16x16 격자 캔버스. 각 칸을 클릭(모바일은 터치)하면 현재 선택된 색으로 칠해진다.
- 색상 팔레트: 기본 제공 색상 여러 개를 버튼/스와치로 보여주고 클릭해서 선택. 커스텀 색상 선택(HTML `<input type="color">`)도 추가.
- 그리기 도구: 최소한 "칠하기(펜)"와 "지우기(투명/배경색으로)" 기능. 드래그하면서 여러 칸을 연속으로 칠할 수 있어야 한다(마우스 down 상태에서 이동, 터치 move).
- 전체 지우기(Clear) 버튼.
- 완성한 그림을 PNG 파일로 저장(다운로드)하는 버튼. `<canvas>`의 `toDataURL`/`toBlob`을 이용해 실제 픽셀 그대로(격자 UI 스타일이 아니라 순수 도트 이미지로) 내보내야 한다. 저장 시 확대(예: 16x16 원본을 각 픽셀당 N배 확대, 예: 320x320)해서 저장하면 실제로 보기 좋다 — 확대 배율은 Plan에서 정해도 된다.

## 산출물
`apps/pixel-art/spec.md` 파일 하나를 작성한다. 내용에는 다음이 포함되어야 한다:

1. **개요**: 앱 설명 한두 문단.
2. **파일 구조**: `/apps/pixel-art/` 안에 만들 파일 목록과 각 파일의 역할.
3. **핵심 로직 설계**:
   - 16x16 픽셀 데이터 구조 (예: 2차원 배열 또는 1차원 배열에 색상 문자열 저장, 빈 칸은 어떻게 표현할지)
   - 격자 UI 렌더링 방식 (CSS Grid로 DOM 칸을 그릴지, `<canvas>`로 그릴지 — 클릭/드래그로 찍는 편의성과 확대 저장(PNG export)을 모두 고려해서 결정하고 이유를 적을 것)
   - 그리기(펜)/지우기 동작 처리, 드래그(마우스 down~move~up, 터치 start~move~end)로 연속 칠하기 처리
   - PNG 저장 로직: 화면에 보이는 편집용 격자와, 실제로 내보낼 순수 픽셀 이미지(확대 배율 포함)를 어떻게 분리해서 만들지 구체적으로 설계 (예: 별도의 오프스크린 `<canvas>`에 각 픽셀을 N배 크기 사각형으로 그린 뒤 `toDataURL('image/png')`로 다운로드)
4. **색상 팔레트 설계**: 기본 팔레트 색상 목록(예: 12~16색 정도, 무채색+기본색 구성 제안), 커스텀 컬러피커 연동 방식, 현재 선택 색상 표시 UI.
5. **입력 처리**: 마우스(mousedown/mousemove/mouseup)와 터치(touchstart/touchmove/touchend) 모두 지원하는 방식, 모바일에서 스크롤과 그리기 제스처가 충돌하지 않도록 하는 방법(`touch-action: none` 등).
6. **UI/디자인**: 레이아웃 구성(팔레트 위치, 격자, 도구 버튼, 저장 버튼), 다크모드 대응, 모바일 반응형(격자 크기가 화면 폭에 맞게 줄어들도록).
7. **작업 순서(체크리스트)**: Build 단계에서 순서대로 구현할 수 있도록 단계별 작업 목록.

계획을 다 작성했으면 `apps/pixel-art/spec.md`로 저장하고, 무엇을 작성했는지 간단히 요약해서 보고하라 (300자 이내).
